# Closing material for Chapter 4: The Optimism of Search

# From Section 4.1 (episode 35): The Best Cross-Validated Score Is the Search's Best Luck

## In practice


- **Do not report the best cross-validated score as the tuned model's performance.** Report a nested cross-validation estimate, or the selected model's score on a test set the search never saw, consulted once.
- **Record how many configurations the search compared.** The more genuinely different models it tried, the less its best score means. Report the count alongside the score.
- **Run the search once on shuffled labels.** Rerun the identical search with the labels permuted and record its best score. That is what the search reports when there is nothing to find; if the real best score is not far above it, most of the score is luck.
- **Keep the untuned default in the comparison, judged on data the search never saw.** Here the default did better on fresh data than the tuned model, although its cross-validated score was lower; a search on few rows can choose worse than not searching.
- **Expect more optimism from broad searches.** Random searches over many hyperparameters and comparisons across model families offer more independent chances than a smooth two-dimensional grid.

## Limits of the evidence


- **Small data on purpose.** At 200 rows the cross-validation noise is large, and so is the optimism. With thousands of rows both shrink, though the optimism still grows with the number of configurations compared.
- **A smooth grid.** Neighbouring configurations of an SVM behave alike, so 64 grid cells are fewer than 64 independent chances. Random search over many hyperparameters, or comparisons across model families, offer more independent chances and more optimism.
- **One model family.** Selecting among different algorithms by their best cross-validated scores adds a second layer of selection on top of this one.
- **Accuracy only.** The same arithmetic applies to any score that is maximised over a search, including AUC and log loss.

## Key points


1. Cross-validation of one untuned model was slightly pessimistic here, by 0.013. The best of 64 cross-validated scores was optimistic by 0.023.
2. On labels that were pure noise, the best of 64 scores averaged 0.575; the selected models scored 0.499 on fresh data.
3. The search's winner scored 0.647 on fresh rows, 0.021 below the best configuration in its grid and below the untuned default's 0.659.
4. Nested cross-validation, which runs the search inside each outer fold, estimated 0.633 against a truth of 0.647 on the task, and 0.524 on noise, where it removed about two-thirds of the optimism.
5. Report a tuned model's performance from nested cross-validation or from a test set the search never saw, and count the configurations tried.

## Exercises


1. Take a model you tuned and record how many configurations the search tried and its best cross-validated score. Shuffle the labels, rerun the identical search, and record its best score. If the second number is not far below the first, explain what that implies about the first.
2. Estimate the same tuned model by nested cross-validation and compare the estimate with the best score from Exercise 1.
3. Explain why the best of several cross-validated scores is biased upwards even though each score on its own is nearly unbiased, and why the bias grows more slowly over a fine grid than over unrelated models.
4. Explain why nested cross-validation tends to be slightly pessimistic, and why that is the same reason plain cross-validation of a single model is.

## Further reading


- Varma and Simon, "Bias in error estimation when using cross-validation for model selection", *BMC Bioinformatics* (2006): the optimism of the best cross-validated score, shown on gene-expression classifiers, and nested cross-validation as the remedy.
- Cawley and Talbot, "On over-fitting in model selection and subsequent selection bias in performance evaluation", *JMLR* (2010): over-fitting of the model-selection criterion itself, and its effect on reported performance.

# From Section 4.2 (episode 67): Five Defensible Choices Turned Coin Flips Into 89%

## In practice


- **Write the analysis plan before looking at any score**: preprocessing, features, model, validation scheme, metric and any subgroups.
- **Count the choices made after looking.** Each one, however defensible, is a step in a search, and the reported score is the maximum of that search.
- **Keep data that no choice touches.** Set aside a test set before the analysis starts, score the final pipeline on it once, and report that number rather than the search's.
- **Put searches inside the validation.** If several models, settings or feature sets must be compared, run the entire comparison inside an outer cross-validation loop.
- **Distrust plausible numbers as much as implausible ones.** On real data an inflated score looks like a normal one; only untouched data can tell them apart.

## Limits of the evidence


- **A greedy walk.** Each step took the best option given the previous ones. A real analyst explores less systematically and sometimes backtracks, which can add more optimism or less.
- **Pure noise as the main case.** With no signal every gain is spurious, so the walk measures optimism at its largest. The breast-cancer version shows the other end; most problems sit between.
- **Five particular choices.** Others are as common: dropping outliers by residual, transforming the target, choosing the metric. Any choice made after seeing a score belongs on the list.
- **Selection on all rows at step one.** Without that leak the later steps would presumably add less, because each would be judged by honest cross-validation; the search would still inflate the maximum, as Section 4.1 measured for tuning. That variant was not run.

## Key points


1. On coin-flip labels, an honest plan reported 0.484; five choices, each taken because it scored best, reported 0.888; the result delivered 0.501.
2. After the first leak, no single step added more than 0.083. The optimism was in the sequence, not in any step.
3. Which model won on noise depended on the data set, because there was no right answer for the search to find.
4. On breast cancer the walk reported 0.977 and delivered 0.965, below the honest plan's 0.974.
5. Write the analysis plan before looking at scores, count every choice made after looking, and report the score of a test set that no choice ever touched.

## Exercises


1. For your last reported result, list every choice made after the first score was seen: features dropped or added, models tried, settings changed, rows excluded, subgroups examined, metrics switched.
2. Count the list. If it is longer than two, the reported number is the best of a search, and the honest number is the one from data that never influenced the list. If no such data exist, describe what you would set aside at the start of the next project.
3. Explain why choosing the better of two subgroups can lower the reported score in a single run and still raise it on average.
4. Explain why the walk on breast cancer could choose a worse model than the honest plan, even though the walk raised the reported cross-validated score.
