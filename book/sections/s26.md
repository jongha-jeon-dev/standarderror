# The Network That Memorises Noise Learns the Signal First

Part V was about training a network; Part VI asks what the trained network has learned. It begins with an argument every student of statistics meets in some form. A model flexible enough to fit any labelling of its training data has learned nothing by fitting this one; a model that generalises must therefore be constrained, by its size, architecture or regularisation, so that it could not have fitted noise. The sentence under test is that argument's conclusion: *a network that generalises could not have fit noise*. A practitioner leans on it whenever a high training accuracy is read as evidence of learning, or a network is trusted because its capacity looks modest. If it is false, training accuracy says nothing about generalisation, and on data with noisy labels only a held-out set can tell when the network has stopped learning the task.

This chapter trains one network on the true labels of a digit data set and on entirely random labels, and shows that it fits both. It argues that capacity therefore cannot be what makes it generalise. It then mixes true and random labels and follows training step by step, finding that the network fits the rows it can generalise from before the rows it can only memorise. Finally it draws the consequence for early stopping.

## The capacity argument and the random-label test

The *generalisation gap* is the difference between a model's error on its training data and its error on new data from the same distribution. Classical learning theory bounds the gap in terms of the *capacity* of the model class, a measure of how many different labellings of a data set the class can fit. A class that can fit only a few labellings cannot fit the training data well by accident, so a good fit means it has found real structure. A class that can fit every labelling offers no such guarantee. The bounds therefore promise a small gap only when the model class is too small to fit arbitrary labels.

Zhang, Bengio and colleagues tested that premise for image networks in 2017 by replacing the labels with random ones. The test is cheap to repeat on the UCI handwritten digits, split in half, stratified by class, into 898 training and 899 test images, with the 64 pixel features standardised on the training half. The network has two hidden layers of 512 ReLU units (64-512-512-10), about 300,000 parameters for 898 training images.

It is trained with Adam, the adaptive optimiser of Chapter 23, at learning rate 1e-3 for 400 steps. Training is *full-batch*: each step uses the gradient on all 898 images, so one step is one pass over the data and the order of examples plays no part. Four label sets are used: the true labels; labels in which 20% or 50% of rows were given a class drawn uniformly at random; and labels that are entirely random. The code reports the step at which training accuracy first reaches 100%, and the final test accuracy.

```python
from standarderror.ml import nets

runs = nets.random_labels()     # 2 x 512 network, full-batch Adam
for r in runs:
    print(f"{r['fraction']:4.0%} of labels randomised: 100% training "
          f"accuracy at step {r['epoch_100']:3d}, test {r['test_acc']:.3f}")
```

```text
  0% of labels randomised: 100% training accuracy at step  41, test 0.968
 20% of labels randomised: 100% training accuracy at step 101, test 0.836
 50% of labels randomised: 100% training accuracy at step  82, test 0.604
100% of labels randomised: 100% training accuracy at step  73, test 0.120
```

## The same network fits true and random labels

On the true labels the network reaches 100% training accuracy in 41 steps and scores 0.968 on held-out digits. On entirely random labels there is nothing to learn, since each label bears no relation to its image. The network reaches 100% there too, in 73 steps, and scores 0.120, chance for ten classes. Fitting pure noise took it less than twice as long as fitting the truth, with no change to architecture, optimiser, learning rate or number of steps.

So the same network, unchanged, can memorise an arbitrary labelling of these 898 images, and by the capacity argument its perfect fit to the true labels should mean nothing. It means a test accuracy of 0.968. The figure below shows the four training curves; the partly random runs are taken up later.

## Why capacity cannot be the explanation

The point Zhang and colleagues made, and this measurement repeats, is that for a network of ordinary size the premise of the classical bounds is false. The model class can fit arbitrary labels, and doing so takes no special effort. A bound that depends only on the model class must allow for the worst case, the random labels, and so cannot promise better than chance. Yet the network generalises well on the true labels.

The two runs differ in one respect only: the labels. Architecture, initial weights, optimiser and schedule are the same. Whatever explains generalisation on the true labels must differ between the runs, and the only candidate is the relation between images and labels. The explanation is a statement about the *data*.

The gradient shows how. On the true labels the images of a class share structure: two images of a 3 have ink in many of the same places. A change to the weights that raises the correct score on one image tends to raise it on the others of that class, so each image's contribution to the gradient pushes in a direction that helps the rest, and the network quickly finds a function that fits many images at once. On random labels no such function exists. Two images of a 3 may carry the labels 5 and 8, and a change that helps one does nothing for the other. The network has to carve out each label individually, which is why it took 73 steps instead of 41. Both end at 100%; the difference is not whether the network can fit the labels but how.

Training accuracy cannot tell the two apart. Only held-out data distinguish a network that has learned the digits from one that has learned a list of image–label pairs.

## With mixed labels, the network fits the signal first

Real data sets usually contain some *label noise*, rows whose recorded label is wrong, so the partly random runs are closest to practice. Here the noise is *uniform*: each affected row receives a class drawn at random, independently of its image.

### Test accuracy rises, then falls

With 20% or 50% of labels randomised the network still reaches 100% training accuracy, in 101 and 82 steps, longer than either pure case. Its test accuracy, though, does not climb steadily. The next block reports each run's best test accuracy, the step where it occurred, and the final value.

```python
for r in runs:
    step, _, best, *_ = max(r["curve"], key=lambda c: c[2])
    print(f"{r['fraction']:4.0%} randomised: best test {best:.3f} at "
          f"step {step:3d}, final {r['test_acc']:.3f}")
```

```text
  0% randomised: best test 0.970 at step 215, final 0.968
 20% randomised: best test 0.928 at step  20, final 0.836
 50% randomised: best test 0.895 at step  15, final 0.604
100% randomised: best test 0.131 at step   1, final 0.120
```

On clean labels the best and final scores are almost equal, 0.970 and 0.968. The partly random runs behave differently. With a fifth of the labels randomised the network reaches 0.928 at step 20, close to the clean network, and ends at 0.836. With half randomised it reaches 0.895 at step 15 and ends at 0.604. Test accuracy rises quickly to an early peak and falls for the rest of training.

### Splitting the training rows by whether their label was changed

To see why, the training rows of the 20% run are divided into unchanged rows, which kept their true label, and changed rows, which were given a random one. The block prints training accuracy on each group, against the labels being trained on, and test accuracy, at five steps.

```python
fifth = runs[1]                  # 20% of labels randomised
for step, train, test, kept, changed in fifth["curve"]:
    if step in (5, 20, 50, 75, 100):
        print(f"step {step:3d}  unchanged rows {kept:.3f}  "
              f"changed rows {changed:.3f}  test {test:.3f}")
```

```text
step   5  unchanged rows 0.880  changed rows 0.030  test 0.835
step  20  unchanged rows 0.973  changed rows 0.024  test 0.928
step  50  unchanged rows 0.999  changed rows 0.358  test 0.901
step  75  unchanged rows 1.000  changed rows 0.891  test 0.850
step 100  unchanged rows 1.000  changed rows 0.994  test 0.833
```

Training falls into two phases. In the first the network learns the unchanged rows and almost ignores the changed ones: by step 20 it is right on 97.3% of the unchanged rows and on 2.4% of the changed ones. That second figure is *below* chance. The natural reading is that the network is predicting the changed rows' true class rather than the random label it is trained on; the curve records accuracy only against the training labels, so this is an inference, not a measurement. It fits the mechanism above: the 80% of correctly labelled rows would define, for each class, a direction of improvement that the changed rows follow too, because they look like the other members of their true class. The network has learned the digits from the rows that teach them and is overruling the noise.

In the second phase it memorises the changed rows one by one: their training accuracy climbs from 0.358 at step 50 to 0.994 at step 100. Test accuracy falls as it does, plausibly because each memorised random label is a small wrong rule about what that digit looks like. The first figure below shows test accuracy for all four runs; the second splits the 20% run into its two groups.

## Why early stopping works, and what it needs

Arpit and colleagues documented the same ordering on larger networks: real patterns are fitted before noise, and the switch is visible in held-out accuracy or in training accuracy split into clean and noisy examples. It is one practical reason *early stopping* works. Early stopping halts training at the step where performance on a held-out validation set is best, rather than at the end of a fixed schedule. A network stopped at the peak has learned the shared structure and not yet the exceptions.

The measurement also says what early stopping needs. The peak came at step 20 in the 20% run and step 15 in the 50% run, and the drop after it was 0.091 and 0.291. Training accuracy gave no sign of either; it was still climbing through the peak, because memorising the changed rows raises training accuracy while it lowers test accuracy. Only a held-out set could see the peak. With noisy labels, which most real data sets have in some proportion, a validation set is not a formality for reporting; it is the only instrument that can tell when the network has stopped learning the problem and started learning the noise.

The ordering also explains why a network trained on clean labels does not suffer from its capacity. With no noise to memorise, the late phase of training has nothing harmful to fit: the clean run reached 0.968 and stayed there through 400 steps.

Here, what the network did after fitting its training data was harmful. Chapter 27 examines a network that has already reached perfect training accuracy, on clean labels, and goes on learning something useful long afterwards.

## In practice

- **Do not read training accuracy as evidence of learning.** A network of ordinary size can reach 100% on labels that mean nothing; only held-out performance separates learning from memorisation.
- **Do not argue from small capacity.** If your network can fit random labels, as networks of ordinary size often can, the evidence that it generalises has to come from data it did not see. To find out, shuffle the training labels and retrain with the same settings.
- **Monitor a validation set at every epoch and keep the best checkpoint.** With noisy labels, validation accuracy can peak early and then fall while training accuracy keeps rising.
- **Report the gap between the peak and the final validation score.** It measures what memorising the noisy rows cost, and what early stopping is buying.

## Limits of the evidence

- **One small network, one data set.** The ordering of signal before noise is a tendency of gradient descent on data with shared structure, not a theorem. It depends on the learning rate, optimiser and architecture, and can be weakened, for instance by very large learning rates or by training on each example many times in a row.
- **Uniform random labels.** Real label noise is rarely uniform. Annotators confuse a 4 with a 9 more often than with a 0, and structured noise of that kind can look like signal to the network and be fitted early.
- **No regularisation.** No weight decay, dropout or augmentation was used. Each would be expected to slow the memorisation of noise and move or flatten the peak; none was tried here. Zhang and colleagues found that such regularisers did not stop their networks fitting random labels.
- **Full-batch training.** One step per pass over the data keeps the comparison clean. With minibatches the same phases would be expected to appear, measured in epochs rather than steps and with more noise; that was not run here.

## Key points

1. A network that generalises can also fit noise. The same network reached 100% training accuracy on true labels in 41 steps (test 0.968) and on random labels in 73 (test 0.120).
2. Capacity therefore does not explain generalisation here. The labels do: on real data, what fits one example of a class fits the rest.
3. Given both signal and noise, the network fitted the signal first. With 20% of labels randomised, by step 20 it was right on 97.3% of unchanged rows and 2.4% of changed ones, and test accuracy peaked at 0.928.
4. Memorising the noise afterwards cost 0.091 of test accuracy with 20% noise and 0.291 with 50%, invisible in training accuracy and visible only on held-out data.
