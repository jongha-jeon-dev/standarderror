# Multiple Choice Grades the Wrong Answers You Offered

There are two common ways to score a language model on a question with one right answer. The first asks for the answer: the model generates a continuation, and the item counts as right if the continuation matches. The second offers options: it computes how likely the model finds each candidate answer, and counts the item right if the true answer is the likeliest. The second is cheap, needs no parsing of free text, and is how many multiple-choice benchmarks are commonly scored. It is usually treated as the same measurement in a more convenient form, which is the sentence this chapter tests: *scoring a model by which answer option it finds likeliest measures the same thing as asking it for the answer.* A practitioner relies on it whenever a multiple-choice score is quoted as evidence that a model can do a task, or used to rank models that will be deployed to generate. If it is false, the score depends on the wrong answers the benchmark happened to offer, and a model can be credited with an ability it does not have.

This chapter scores the same models on the same problems both ways. It first shows models that cannot generate a single right answer to a set of problems but pick the right answer from four options almost every time, and explains how. It then shows that the multiple-choice score is set by the kind of wrong options offered, and that the choice of options can erase a real difference between two models. Finally it examines length normalisation, the usual correction for options of different lengths.

## Two scoring rules for the same question

### Generation and likelihood scoring

Under *generation scoring* (also called *exact match*), the model is given the question and produces its answer one character at a time until it ends the line. The item is right if the produced string equals the true answer.

Under *likelihood scoring*, the model produces nothing. For each option $a$, made of characters $a_1, \dots, a_L$, it computes the log-likelihood of that option following the question $q$,

$$
\log P(a \mid q) = \sum_{t=1}^{L} \log P(a_t \mid q, a_1, \dots, a_{t-1}),
$$

and the item is right if the true answer has the largest log-likelihood. The wrong options are called *distractors*. Evaluation harnesses such as the widely used lm-evaluation-harness of Gao and colleagues report this accuracy both as it stands and with *length normalisation*, where each option's log-likelihood is divided by its length in characters or bytes before the comparison.

### The models and the length probe

The models are the small arithmetic transformers of Part XI, trained in this book's repository: four blocks, 804,096 parameters, trained on generated sums with held-out probes. They are tiny, and that is the reason to use them: every answer can be checked exactly, so each scoring rule can be compared with the truth rather than with another score. Three are used here: the main model; its leaky twin, trained on the same data unshuffled; and a 6,000-step snapshot of a separate, shorter run, which is much weaker. Each problem has one context of twelve random training lines in front of it, shared by both scoring rules.

The first test set is the *length probe*: four-digit sums, whereas the models saw operands of up to three digits in training. The code generates the main model's answers to 200 of them and prints four, then the exact-match accuracy and the share of answers shorter than the truth.

```python
import numpy as np
from standarderror.ml import llmeval as le
from standarderror.schoolmath import arithmetic as ar
from standarderror.schoolmath import model as sm

model = sm.load()                      # the main arithmetic model
sums = le.items("probe_length", "add", 200)     # four-digit operands
fills = ar.fillers(len(sums), seed=9)  # one fresh context per problem
rows = ar.graded(model, sums, filler=fills)
for r in rows[:4]:
    print(f"{r['prompt']:12s} want {r['want']:6s} got {r['got']}")
print("exact:", np.mean([r["ok"] for r in rows]),
      " shorter than the answer:",
      np.mean([len(r["got"]) < len(r["want"]) for r in rows]))
```

```text
7755+2656=   want 10411  got 1030
2216+1490=   want 3706   got 769
2669+5296=   want 7965   got 795
8625+8412=   want 17037  got 1603
exact: 0.0  shorter than the answer: 0.995
```

None of the three models generated a single right answer to the 200 four-digit sums. The main model's failures have a pattern: 99.5% of its answers were shorter than the truth, typically a truncated version of roughly the right number. The first digit was right in 90% of them, the first two in 61%, and 25.5% were an exact prefix of the answer. The model starts four-digit answers well and stops too soon.

## Picking an answer the model cannot produce

Offer the main model the same sums as four options, the right answer and three random numbers with as many digits, and it picks the right one 0.955 of the time. Its twin scores 0.980, and the short run, which generates far fewer answers correctly than either (0.205 on multiplication), scores 0.790. Nothing about the models changed between the two scoring rules, only the question asked of them. The figure below compares the rules across four tasks.

### Why a truncating model wins against random options

The reason is visible in the generations. A model that writes a truncated version of nearly the right number puts most of its probability on strings that start with the right digits. An option's log-likelihood is the sum of per-character terms in the formula above, and the first characters, where the model is most often right, weigh heavily in the comparison. A random number of the same length almost never shares the true answer's leading digits, so each of its early characters is unlikely and its total log-likelihood is far below the true answer's. The true answer wins without the model ever being able to finish it.

Multiple choice therefore measures whether the model prefers the right answer to the wrong ones offered. That is a real ability, closer to recognition than to production, and it is a different one from generating the answer.

### The distractors set the score

The next block takes the first sum and offers it with three kinds of distractor: random numbers of the same length; *near misses*, which differ from the answer by a one-digit slip; and options of different lengths, made by dropping, appending or prepending a digit. It prints which option the model finds likeliest.

```python
rng = np.random.default_rng(2)
p = sums[0]
for kind in ("random", "near", "length"):
    options = [p.answer] + le.distractors(p.answer, kind, rng)
    lp = le.answer_logp(model, [p.prompt] * 4, options, [fills[0]] * 4)
    pick = options[int(np.argmax(lp))]
    print(f"{kind:6s} options {options}  picked {pick}")
```

```text
random options ['10411', '19837', '33545', '85381']  picked 10411
near   options ['10411', '10410', '10421', '19411']  picked 10411
length options ['10411', '1041', '110411', '910411']  picked 1041
```

Against random options and near misses the model picks 10411 for this sum; against options of different lengths it picks 1041, the truncated answer it would have generated.

Over all 200 sums, the score is set by the wrong answers. Against one-digit slips, the errors a person or a model actually makes, the main model's score fell to 0.395. Near misses share most of the answer's digits, so the leading digits no longer decide the comparison. Against options that differ in length the score fell to 0.315, barely above the 0.25 of guessing among four options, and in 68% of items the option the model preferred was shorter than the answer: the same truncation it generates. That gives three numbers anyone could publish, 0.955, 0.395 and 0.315, for one model on one set of questions.

## Which model is better depends on the options

Within the training lengths the gap between the two scoring rules is smaller, but still not a constant that cancels when models are compared. On multiplication the main model generated 0.755 of answers correctly and its leaky twin 0.650, a clear lead. Against near-miss options the twin scored 0.895 and the main model 0.880: a lead of 0.105, more than two standard errors, became a difference well inside one. On problems mixing addition and multiplication, generation put the two models level (0.410 and 0.400) and multiple choice put the twin ahead by 0.050, about one standard error. On three-digit carries both rules agreed that the twin was better. Neither rule's ranking is free of noise on 200 problems; what is not noise is the size of the multiplication gap under one rule and its absence under the other.

Against random distractors every model scored 0.99 or more on multiplication and mixed operations (the short run scored 0.97 on three-digit carries), including the short run, which generates 0.205 of multiplications correctly. A benchmark scored that way cannot tell the three models apart. The table below gives every model, task and rule.

![Each block of three rows is one task; MC is multiple choice among four options. Generation ranges from 0 to 0.755; multiple choice against random numbers is 0.79 or higher everywhere.](ml154-f1-table.png){alt="A twelve-row table. Generation ranges from 0 to 0.755; multiple choice against random numbers is 0.79 or higher everywhere."}

Schaeffer and colleagues made a related point about apparently "emergent" abilities of large models: a discontinuous metric such as exact match, which gives no credit for a nearly right answer, can make smooth improvement look sudden. Here the arrow runs the other way: a lenient metric made a large real gap look like none. Chapter 47 found the same pattern for classifiers, where the model with the best AUC was never the cheapest once a miss cost ten times a false alarm. A summary that does not match the use can rank models in a different order from the decision they serve.

## Length normalisation did nothing here

The usual worry about likelihood scoring is length. Because an option's log-likelihood is a sum of one negative term per character, a longer option accumulates more terms and tends to look less likely regardless of whether it is right. Harnesses therefore offer a per-character or per-byte average to correct for it.

Here the correction moved no score by more than 0.040, and every score but one by 0.010 or less. Most option sets had a single length, so there was nothing to correct. In the length-varied set, a likely reason is that each option is scored together with its closing newline, which charges a short option for stopping early; that was not tested separately.

That is a result about these options, not a general reassurance. Benchmarks whose options are sentences of different lengths are exactly where the two versions are known to disagree, which is why harnesses report both. The point that does generalise is that the choice between them is one more scoring decision, made before any model is run, on which the headline number depends.

The scoring rules in this chapter still compare an answer with a known truth. Chapter 55 removes the truth, and asks whether a model can grade other models' answers in its place.

## In practice

- **Treat a multiple-choice score as accuracy against those particular distractors.** State what the distractors are, and how they were made, whenever the number is reported.
- **Report generation where the use is generation.** If the model will be asked to produce answers, measure it producing answers; a high multiple-choice score does not show it can.
- **Test the distractors.** Rescore a sample of items with plausible near-miss options. A large drop means the original score was measuring how easy the wrong answers were to reject.
- **Check rankings under both rules.** If two models' order changes between generation and multiple choice, the comparison depends on the rule, and the rule should match the use.
- **State the normalisation.** Report whether option log-likelihoods were divided by length, and in what units.

## Limits of the evidence

- **Arithmetic, not language.** Real multiple-choice benchmarks such as MMLU (Hendrycks and colleagues, 2021) have options written by people, and are often scored by the letter the model picks rather than by the likelihood of the answer text. Scoring the letter is a third rule, with its own failure modes, and it was not measured.
- **Small models.** Large models can be asked to choose explicitly and may reason before answering, and the gap between recognising and producing may be smaller for them. The mechanism shown here, a partial answer that still beats unrelated options, is not specific to small models, though how often it operates in a large one was not measured.
- **Distractors of three invented kinds.** A benchmark's distractors are usually chosen to be plausible to people, which is closer to the near-miss column than to the random one; how close is a property of each benchmark.
- **200 problems per cell.** Differences of a few points between models under near-miss multiple choice sit within about one standard error; the large gaps between scoring rules do not.

## Key points

1. Three models that generated no four-digit sum correctly picked it from four options 0.955, 0.980 and 0.790 of the time against random distractors.
2. A model that produces the right leading digits can win against random options without being able to finish the answer; multiple choice measures something closer to recognition than to production.
3. The main model's score on the same sums was 0.955, 0.395 or 0.315 depending only on the kind of wrong options offered.
4. The main model's 0.105 lead over its twin in generating multiplications disappeared under near-miss multiple choice; against random options every model scored at least 0.99 on multiplication and mixed operations.
5. Treat a multiple-choice score as accuracy against those particular distractors. Report generation where the use is generation, and state the distractors and the normalisation along with the number.
