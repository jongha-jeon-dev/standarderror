# Augmentation Adds an Assumption, Not Data

*Data augmentation* is the practice of enlarging a training set with transformed copies of its examples: each training image is shifted, rotated, flipped or overlaid with noise, and the copies are trained on under the original's label. It is the most common way of encoding a preference about the data themselves, in the way that Chapter 27's weight decay encoded a preference for small weights that the training data could not express. The usual description of it is the sentence under test: *data augmentation adds data*. Four copies of every image make five times the training set, for free. Practitioners act on this when they reach for augmentation as a substitute for collecting more examples, or apply a standard list of transformations without asking whether each is appropriate to their data. If the sentence is false, augmentation can cost accuracy where it was expected to add it, and its benefit can lie somewhere the ordinary test set never looks.

This chapter compares augmented copies with real extra examples on the handwritten digits, scoring both on an ordinary test set and on a test set whose digits have been moved. It then shows what shifted copies teach, measures what happens when a transformation changes the label, and closes by reading augmentation as a prior assumption about the world the model will meet.

## Augmented copies against real extra examples

If augmentation literally added data, augmented copies would do what the same number of new, real examples does. On the digits that can be tested directly, because the data set holds far more real images than a small experiment needs. The experiment takes 150 training digits and trains six networks, each with one hidden layer of 128 units:

- *base*, on the 150 digits alone;
- *real*, on 750 real digits;
- *shift*, on the 150 plus four copies of each moved by up to a pixel;
- *noise*, on the 150 plus four copies with random noise added to the pixels;
- *flip*, on the 150 plus mirrored copies;
- *rot180*, on the 150 plus copies turned through half a revolution.

Every network takes the same number of gradient steps, exactly 300 minibatches of 32 with SGD and momentum, so none wins by training longer. All are scored on 700 held-out digits, and on the same 700 moved by up to a pixel in each direction. The whole comparison is repeated over ten random splits, and the code prints the average accuracies.

```python
from standarderror.ml import nets

r = nets.augmentation()      # 150 real digits, 4 copies each, 10 splits
for k in ("base", "real", "shift", "noise", "flip", "rot180"):
    print(f"{k:7s} test {r[k]:.3f}   moved test {r['moved'][k]:.3f}")
```

```text
base    test 0.917   moved test 0.367
real    test 0.957   moved test 0.383
shift   test 0.889   moved test 0.687
noise   test 0.918   moved test 0.369
flip    test 0.825   moved test 0.302
rot180  test 0.794   moved test 0.292
```

Read the first column, the ordinary test set. Four times more real digits raised test accuracy by 0.041. Four shifted copies of each image changed it by -0.027: they made the network worse, by more than five standard errors (the standard error is 0.005). Noisy copies changed it by +0.001, which is nothing. Mirrored and half-turned copies made the network substantially worse, by 0.092 and 0.123. On the ordinary test set, none of the augmentations behaved like real data. The figure below shows what the copies look like.

![The shifted and noisy copies keep the label. The mirrored 3 is no longer a 3, the half-turned 6 is a 9, and the mirrored 0 is still a 0.](ml128-f0-grid.png){alt="A five-by-five grid of 8 by 8 pixel digits: the shifted and noisy copies still read as the same digit; the mirrored 3 and the half-turned 6 and 7 read as something else or nothing."}

## Shifted copies teach one fact, which the ordinary test set never asks

The second column changes the picture. On test digits moved by up to a pixel, the network trained on 150 digits scores 0.367. It has hardly seen a digit off centre, because the digits in this data set barely move within their frame. The centre of each image's ink has a standard deviation of 0.30 of a pixel across and 0.39 down, only 0.7% of images have it more than a pixel from the average, and the leftmost column of pixels holds ink in 0.2% of images. A network with one hidden layer on raw pixels treats each pixel as a separate input with its own weights, so a one-pixel move puts strokes on pixels it has learned to ignore and takes them off the pixels it relies on.

More real digits do not fix this: 750 centred digits score 0.383 on the moved test set, a change of +0.016. Shifted copies of 150 digits score 0.687, a gain of 0.320.

So the two kinds of extra data taught different things. The real digits taught more about what digits look like: more writers, more ways of drawing a 4. The shifted copies taught nothing about that. They taught one fact, that a digit moved by a pixel is the same digit, and the ordinary test set never asked about that fact, because nothing in it was moved. It charged for the lesson anyway: 0.027 of accuracy on centred digits. A likely reason is the training budget. Every network took the same 300 steps, and for the shift network four-fifths of what it saw was shifted, so it spent most of its training on positions the test set never uses.

That is what an augmentation is. It is not data in the sense of new observations of the world. It is a statement, made by the person training the model, that the label is *invariant* under some transformation: unchanged when the transformation is applied to the input. The network cannot learn that statement from centred digits, because centred digits contain no evidence about moved ones either way. The augmentation supplies it from outside the data, as an assumption, and the assumption is worth exactly as much as the test data's variation along it. The figure below sets the gains on the two test sets side by side.

![Shifted copies changed accuracy by -0.027 on the test digits and +0.320 on the moved ones; four times more real digits by +0.041 and +0.016.](ml128-f1-bars.png){alt="Paired bars: real data helps on clean test digits and barely on moved ones; shifted copies cost a little on clean digits and add about 30 points on moved ones; mirrored and half-turned copies lose on both."}

## When the transformation changes the label

Mirrors and half-turns are ordinary augmentations for photographs, where a mirrored cat is still a cat. They do not preserve the label for digits. To measure how far they fail, a network trained on clean digits is shown mirrored or half-turned test digits, and the code prints, for each true class, how often it gives an answer other than that class.

```python
f = nets.flip_confusions()
for kind in ("flip", "rot180"):
    print(f"{kind:6s} " + "  ".join(f"{d}:{v:4.0%}"
                                    for d, v in f[kind].items()))
```

```text
flip   0:  3%  1: 36%  2: 80%  3: 99%  4:  9%  5:100%  6:100%  7: 89%  8: 15%  9: 65%
rot180 0:  3%  1: 30%  2: 58%  3:100%  4: 14%  5: 55%  6:100%  7:100%  8: 18%  9:100%
```

A mirrored 3, 5 or 6 is almost never read as itself, and neither is a half-turned 3, 6, 7 or 9: each is read as its own class in at most 1% of cases. To a human eye a half-turned 6 is a 9. Zeros survive both transformations, and eights mostly do. Training on these copies under their original labels therefore tells the network, among other things, that the shape of a 9 is evidence for a 6. That is false, and the network pays for it: -0.092 from mirrors and -0.123 from half-turns, against the network that saw only the 150 originals. On the moved test digits they cost too, -0.065 and -0.075.

Pixel noise is the control. Its copies preserve the label, and it changed nothing: +0.001 on the ordinary test set and +0.002 on the moved one. Neither test set contains noisy pixels, so the invariance it teaches is never asked for, and at a standard deviation of 2 on a 0-to-16 scale it does not disturb the image enough to get in the way. Copies that assert something true but irrelevant are simply wasted. The table below collects the results.

![Only real data helped on the clean test digits by more than two points. Only shifted copies helped on the moved ones by more than ten.](ml128-f2-table.png){alt="A six-row table of accuracies on clean and moved test digits for each training set."}

## Augmentation as a prior

Chen, Dobriban and Lee make this reading precise. Suppose the transformations form a *group* $G$, a set closed under composition and inversion, such as all shifts or all rotations, and the true label is invariant under every $g$ in $G$. The *orbit* of an input $x$ is the set of all its transformed versions $gx$. Training on augmented data is then equivalent to replacing the loss on each example by its average over the orbit,

$$
\frac{1}{|G|}\sum_{g \in G} \ell\big(f(gx),\, y\big),
$$

for a finite group, where $f$ is the model and $\ell$ the loss. When the label really is invariant, this averaging can only reduce the variance of what is learned, and it introduces no bias. When the label is *not* invariant, the same averaging introduces bias, because it trains the model on a distribution that does not exist: one in which a half-turned 6 is labelled 6.

Both halves were visible here, along with a cost the theory does not count. Shifts are close to an invariance of handwriting, and the shifted copies bought 0.320 where shifts actually occurred. On a fixed budget of training they still cost 0.027 where shifts did not. A true assumption may be free in the limit, but on 300 steps it was not, plausibly because of the budget; giving every network an equal number of epochs was not tried. Mirrors and half-turns break the label for at least three classes, and their cost was large wherever they were scored.

The practical reading is that an augmentation should be chosen the way a *prior* is chosen in Bayesian statistics, as an assumption brought to the data rather than learned from it: by asking what is true of the world the model will see, not what makes the training set bigger. A shift augmentation suits a camera that may not be centred; a colour jitter suits a model that will meet different lighting. Text should not be mirrored, digits should not be turned through half a revolution, and a sequence with a direction should not be reversed in time. The question is never how many copies, but whether the test data will vary in the way the copies do, and whether the label survives that variation.

An augmentation is a guess about how test inputs will differ from training inputs. Chapter 29 measures what happens when the inputs really do move between training and test, and what that movement costs.

## In practice

- **Do not count augmented copies as data.** They add an assumption, not observations. Judge an augmentation by a held-out comparison with and without it, not by the size of the enlarged training set.
- **Build a test set that varies the way you expect deployment to vary.** An augmentation's benefit may be invisible on an ordinary test set and large on a shifted one. Score with and without the augmentation on both.
- **Check that each transformation preserves the label.** Look at a sample of augmented images with their labels. Mirrors, half-turns, crops and time reversals can all change the class of some examples.
- **Watch the training budget.** With a fixed number of steps, augmented copies displace the original examples, and a true but unneeded invariance can cost accuracy on the ordinary test set.
- **Drop augmentations whose invariance the test data never exercise.** They are wasted at best.

## Limits of the evidence

- **A small network on centred images.** One hidden layer on raw pixels has no built-in tolerance for position, which is why a one-pixel move costs it so much. A convolutional network with *pooling*, which summarises each small neighbourhood of a feature map by its maximum or mean, builds part of the shift invariance into its architecture and needs the augmentation less. The point about what augmentation supplies is the same; the size of the effect is specific to this model.
- **Equal steps, not equal epochs.** Every network took exactly 300 gradient steps, so each image in the augmented and the larger real sets was seen fewer times. Giving every network the same number of epochs instead would have given the 150-digit network a fifth of the steps, a different comparison.
- **One kind of shift.** The moved test set uses exactly the transformation the shift augmentation uses. Test data that vary in a different way, by rotation of a few degrees or by thickness of stroke, would reward a different augmentation and not this one.
- **Small data.** With 150 training images every source of information shows. With tens of thousands, real data already contain much of the variation, and augmentations matter mostly for the invariances the real data never exhibit.

## Key points

1. Augmented copies are not new observations. On the ordinary test digits, four times more real data added 0.041; four shifted copies of each image changed accuracy by -0.027, and noisy copies by +0.001.
2. An augmentation asserts that the label survives a transformation. Shifted copies added 0.320 on test digits moved by a pixel, where four times more centred real digits added 0.016.
3. A false assertion costs accuracy. Mirrors and half-turns change the label of at least three digit classes, and training on them cost 0.092 and 0.123.
4. Choose augmentations by the variation the test data will have and the label will survive, not by how much they enlarge the training set.
