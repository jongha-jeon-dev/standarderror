# Not Every Leak Leaks, and the Ones That Do Can Be Measured

Chapter 2 established what cross-validation estimates: the average error of a training procedure. This chapter is about the most common way to make it estimate something else. Every course teaches the rule: *fit every preprocessing step inside the folds.* Anything fitted to data, whether a scaler, an imputer, a feature selector or an encoder, must be fitted on each training fold and only applied to the held-out fold, never fitted on all the rows first. A violation is called *leakage*: information from the rows used for evaluation reaches the model through the preprocessing, and the evaluation becomes optimistic. Kapoor and Narayanan found leakage in hundreds of published papers across seventeen fields.

The rule is right. What the usual teaching leaves out is that violations differ in size by orders of magnitude, and that the size can be reasoned about from what the step does. That matters in practice, because the expensive question is rarely "did we leak?" but "how much of the reported number is leak?"

The chapter measures seven violations, each against its honest version on the same folds. It starts with the best-known case, feature selection on pure noise, and shows that the leak grows with the number of candidates. It then measures six more violations on real data, which range from nothing to several points. It ends with a rule for sizing a leak before measuring it.

## Feature selection on noise: the classic leak

The best-known leak needs no real data at all. Each simulated dataset has 100 rows, 5,000 features of standard-normal noise, and labels from a fair coin, so no model can do better than 0.5 accuracy on new data. A common pipeline picks the 20 features most associated with the label and then cross-validates logistic regression on them. The code runs that pipeline on 50 such datasets in two ways: selecting on all rows before cross-validating (leaky), and selecting inside each training fold (honest).

```python
from standarderror.ml import leakage as lk

# 100 rows, 5,000 noise features, coin-flip labels, 50 datasets.
r = lk.noise_selection(n=100, p=5000, k=20, reps=50)
print(f"select on all rows, then CV:  {r['leaky'].mean():.3f}"
      f"   (lowest {r['leaky'].min():.2f})")
print(f"select inside each fold:      {r['honest'].mean():.3f}"
      f"   (highest {r['honest'].max():.2f})")
```

```text
select on all rows, then CV:  0.880   (lowest 0.80)
select inside each fold:      0.525   (highest 0.63)
```

Selected on all rows, coin flips cross-validate at 0.880, and none of the fifty datasets came in below 0.80. Selected inside each fold, the estimate is 0.525, which is what labels from a coin deserve. This is the result Ambroise and McLachlan reported for microarray studies in 2002, reproduced in a few lines.

## The size of a selection leak is the room to choose

The mechanism is worth spelling out. The selection step computes, for each of the 5,000 features, how strongly it is associated with the label, and it does so using all 100 labels, including the ones each fold will later hold out. Each noise feature's association with the labels is a small random number, positive or negative. Among 5,000 such random numbers, the largest 20 are far from zero by chance alone. The selected columns therefore line up with the labels, including the held-out labels, by construction. Cross-validation then faithfully measures how well those columns predict labels they were chosen to predict. When selection happens inside each fold, the held-out labels play no part in the choice, and the selected columns are just noise to them.

That argument implies that the size of the leak is set by how much choice the step has: the more candidates, the more extreme the best chance alignments. The experiment confirms this by sweeping the number of noise candidates from which the 20 are chosen.

The leak is exactly zero with 20 candidates, because there is nothing to choose, and climbs steadily: 0.63 with 50 candidates, 0.74 with 200, 0.84 with 1,000 and 0.88 with 5,000. The honest line never moves off 0.5. The figure below shows both lines.

![With 20 candidates there is nothing to choose and nothing leaks. With 5,000 the leaky estimate is 0.88 for labels that are coin flips.](ml103-f0-sweep.png){alt="A rising line from 0.5 to near 0.9 as the number of noise candidates grows, and a flat line at 0.5."}

## Six violations on real data

On the Wisconsin diagnostic breast cancer data, 569 rows and 30 real features, six more violations are measured, each scored against its honest version on the same 20 fold assignments, so that the difference is attributable to the leak alone. The six are:

- *Standardising* on all rows: subtracting each feature's mean and dividing by its standard deviation, with both estimated from every row.
- *Mean imputation* on all rows: filling missing values with each feature's mean over every row.
- *Target encoding* a noise ID on all rows. Target encoding replaces each level of a categorical column by the mean label of the rows at that level. Here the column is 200 random categories with no relation to the label.
- Selecting 5 of 1,030 features on all rows: the 30 real features plus 1,000 columns of pure noise.
- Duplicating every row and splitting at random, for logistic regression and for 1-NN, the nearest-neighbour classifier that predicts each row's label from the single closest training row.

The code prints the honest and leaky accuracies and the gap in points.

```python
for row in lk.leak_table(reps=20):
    print(f"{row['leak']:40s} honest {row['honest']:.4f}  "
          f"leaky {row['leaky']:.4f}  {row['gap'] * 100:+.2f}")
```

```text
standardise on all rows                  honest 0.9790  leaky 0.9795  +0.05
impute means on all rows                 honest 0.9664  leaky 0.9662  -0.02
target-encode a noise ID on all rows     honest 0.9616  leaky 0.9859  +2.43
select 5 of 1,030 features on all rows   honest 0.9454  leaky 0.9454  +0.00
duplicate rows across folds (logistic)   honest 0.9768  leaky 0.9858  +0.90
duplicate rows across folds (1-NN)       honest 0.9522  leaky 0.9895  +3.74
```

### Steps that estimate a mean or scale leak nothing measurable

Standardising and imputing on all rows leak +0.05 and -0.02 points: nothing measurable. Neither step looks at the label. Each estimates a handful of summary statistics per feature, and a mean or standard deviation estimated from 569 rows instead of 455 differs by too little to move a decision boundary. These are the violations easiest to spot by reading the code, and here they were the least consequential.

### Label-informed selection leaks only where there is room to fit chance

Selecting features on all rows leaked nothing either, +0.00 points, even though the selection looked at every label and chose 5 of 1,030 columns, 1,000 of them pure noise. The real features are so much stronger than any noise column's chance alignment that the selection picks them whether or not it sees the held-out labels. The noise experiment leaked because there was nothing real to find, and every choice was a chance alignment. Using the label is therefore necessary for this kind of leak, but not sufficient. What leaks is the room to fit chance.

### Target encoding hands the model the held-out labels

Target-encoding a noise ID leaks +2.4 points. The column carries no information about the label. But when the encoding is computed on all rows, each category's mean label includes the held-out rows' own labels. With few rows per category, a row's own label is a substantial part of the mean that replaces its category, so the encoded value partly *is* the label, and the model learns to read it back. Fitted inside the folds, the held-out rows' labels never enter the means, and the column is worthless, as it should be. Chapter 40 shows that even the honest version can leak, into the training rows rather than the test rows.

### Duplicates leak without looking at the label

Duplicated rows leak +0.9 points for logistic regression and +3.7 for 1-NN, although no step looked at the label at all. If every row is copied once and the rows are split into folds at random, most copies land in a different fold from their twin, so most held-out rows have an exact copy in the training data.

How much that helps depends on how local the model is. Logistic regression fits a smooth boundary from all training rows, and one extra row near a test point moves that boundary only a little: it gains slightly from having seen its test row. A nearest-neighbour model, by contrast, *is* a lookup: if the test row's twin is in training, its nearest neighbour is at distance zero and carries the right label. The leaky 1-NN score is almost exactly what that predicts. With about 80% of twins in another fold, and the rest scored as the honest model would score them,

$$
80\% \times 1 + 20\% \times 0.952 = 0.990,
$$

against 0.990 measured. The figure below sets the six real-data leaks side by side.

![Neither colour predicts the size. Looking at the label is necessary for a selection leak and not sufficient; duplicates leak without looking at it at all.](ml103-f1-leaks.png){alt="Horizontal bars: three at or near zero for standardising, imputing and feature selection, and three clearly positive for target encoding and the two duplicated-row cases."}

## A rule for sizing a leak

The measurements support one rule of thumb, sharper than "fit everything inside the folds": *a step leaks to the extent that it gives the model room to fit the test rows.* That room comes from two places.

The first is choice informed by the labels: feature selection, target encoding, hyperparameter tuning. Its size is set by how many options the step has relative to how much real signal there is to find. With plenty of real signal, the choice is made the same way with or without the held-out labels, and nothing leaks. With pure noise, every candidate is a chance to fit them, and the leak grows with the number of candidates.

The second is the test row itself, or a near-copy of it, being present in training. Its size is set by how local the model is: logistic regression barely notices a duplicate; 1-NN returns it.

Steps that do neither, such as estimating a mean, a scale or a missing-value fill from a few hundred rows, do not leak in any amount worth measuring. Fit them inside the folds anyway, because it costs nothing. But when auditing a result, start with the steps that can choose and with any way a row can appear on both sides of a split. Leakage inflates an estimate at one sample size. Chapter 4 turns to estimates across sample sizes, and asks whether a learning curve can say what more data will buy.

## In practice

- **Measure a suspected leak instead of debating it.** Run the cross-validation with the step fitted on all rows and again fitted inside the folds, on the same fold assignment, and subtract. Compare the difference with the error bar from Chapter 1.
- **Audit label-informed choices first.** Feature selection, target encoding and tuning on the evaluation folds are where leaks of many points live, and they are largest when there are many candidates and little real signal.
- **Look for rows on both sides of a split.** Exact and near-duplicates leak without touching the label, and they matter most for local models such as nearest neighbours.
- **Fix the cheap violations, but do not panic about them.** Standardising and mean imputation on all rows are worth moving inside the folds as a matter of hygiene; on a few hundred rows they did not move the score.
- **Report the leak-free number.** If a measured leak is larger than the error bar, the reported score was partly the leak, and the honest version is the one to report.

## Limits of the evidence

- **Small data makes the harmless steps less harmless.** At 569 rows a scaler fitted on 455 or 569 rows is the same scaler. With 30 rows and a heavy-tailed feature it would not be, and standardising could leak a little through one extreme row.
- **Real duplicates are rarely exact.** Near-duplicates, such as augmented images, resampled time series or the same patient twice, leak by the same mechanism with less force and are much harder to find. The 1-NN number is the upper end of the range. Chapter 37 treats the related case of many rows from the same people.
- **Tuning is the leak not measured here.** Choosing hyperparameters on the same cross-validation you report is label-informed choice, so by the rule above its size depends on how many configurations were tried and how much they differ. The best of many configurations looks good on noise for the same reason the selected features do; Chapter 35 measures that optimism.
- **One dataset.** The breast cancer features are strong, which is why selection leaked nothing on them. On a dataset with weak signal and many features, the setting where selection is used most, it will look much more like the noise experiment.

## Key points

1. Fitting a step on all rows before cross-validating can leak anything from nothing to a third of the accuracy scale. Measure it: run the honest version on the same folds and subtract.
2. Standardising and mean imputation on all rows leaked +0.05 and -0.02 points here. Not worth an alarm; still worth fixing.
3. Feature selection on all rows turned coin flips into 0.88 accuracy, growing with the number of candidates, and leaked +0.00 on real data where the real features dominate.
4. Target encoding on all rows leaked +2.4 points from a column of pure noise, and duplicates leaked without touching the label: +0.9 points for logistic regression and +3.7 for 1-NN.
5. A step leaks to the extent it gives the model room to fit the test rows: label-informed choice, or the test row itself in training.
