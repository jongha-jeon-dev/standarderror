# Scores, Error Bars and Comparisons

A test score is the number most machine-learning decisions rest on. A model replaces the one in production because it scored higher, a method earns its place in a table because it tops the column, a hyperparameter is chosen because its validation score was best. Each of these readings treats the score as if it described the model exactly, and treats two models that score the same as interchangeable. This chapter measures how far a single test score can carry those readings, on data small enough to rebuild anywhere: the UCI handwritten digits, a simulated task whose best possible error is known, and the breast-cancer data bundled with scikit-learn.

The chapter has two sections, each built around a sentence that practitioners rely on, usually without saying it aloud:

- Section 1.1: *the model with the higher test score is the better model.*
- Section 1.2: *two models with the same accuracy make the same predictions.*

The first sentence is about scores that differ. A test accuracy is a proportion estimated from a finite number of rows, so it has a standard error, and on a test set of a few hundred rows that error bar is often wider than the gain being reported. Section 1.1 puts an error bar on a test score, shows that repeating the random split measures less than it appears to, and replaces two separate error bars with a paired comparison: score both models on the same rows, count the rows on which only one of them is right, and ask how many rows a difference of the observed size would need before a test could detect it.

The second sentence is about scores that tie. Section 1.2 takes the rows on which two models disagree, the same discordant rows that drive the paired comparison of Section 1.1, and asks how many of them there can be when the two accuracies are equal. The answer depends on how often the models are wrong. When errors are rare, equal accuracy forces nearly identical predictions. When the task has a large irreducible error, models of equal accuracy can disagree on a large share of rows, and the choice between them decides which answer a particular person receives.

The two sections therefore read a test score from both ends: when a difference in scores does not establish a difference in models, and when equal scores do not establish equal models. Together they set up the habits the rest of the book assumes: report a score with its error bar, compare models on the same rows, count disagreements as well as accuracy, and record a difference the data cannot resolve as unresolved. Both sections take the fitted model as given and ask what its test score can say about it. They leave open how much the score depends on the particular training data, which is where Chapter 2 begins.

## Your Test Score Has an Error Bar, and It Is Wider Than Your Gain

<!-- source: ml-1-error-bar; hero: ml101-hero.png -->


Almost every model comparison rests on one sentence: *the model with the higher test score is the better model.* It sits behind every leaderboard and every decision to replace a production model with a challenger that scored a point higher. Every later chapter of this book compares scores, so every later chapter leans on it. If it fails at the sizes practitioners work with, many reported improvements are differences in which test rows happened to be drawn.

This section measures the sentence on three classifiers and the UCI handwritten digits, in three steps. It first treats a test accuracy as a proportion estimated from a finite sample and gives it an error bar. It then examines the usual remedy for a noisy split, repeating the split, and shows with a control experiment that the repetition measures something narrower than it appears to. Finally it compares the models on the same rows with McNemar's test, and asks how many rows the comparison at the top of the leaderboard would need.

### A test accuracy is a proportion with a standard error


The data are the UCI Optical Recognition of Handwritten Digits as bundled with scikit-learn: 1,797 images of 8x8 pixels. Three classifiers, logistic regression, a support vector machine with a radial basis function kernel (RBF SVM) and a 3-nearest-neighbour classifier (3-NN), are trained on a *stratified* 80/20 split, one that preserves each class's proportion in both halves. The test set has 360 images. The code prints each test accuracy with a 95% interval half-width.

```python
from sklearn.model_selection import train_test_split
from standarderror.ml import evaluation as ev

X, y = ev.digits()
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.2,
                                      random_state=0, stratify=y)
for name, make in ev.models().items():
    acc = (make().fit(Xtr, ytr).predict(Xte) == yte).mean()
    print(f"{name:9s} {acc:.4f}  +- {1.96 * ev.binomial_se(acc, len(yte)):.4f}")
```

```text
logistic  0.9667  +- 0.0185
RBF SVM   0.9861  +- 0.0121
3-NN      0.9861  +- 0.0121
```

Read the usual way, the SVM beats logistic regression by 1.9 points and ties 3-NN exactly. The numbers after the `+-` change that reading.

If the test rows are an independent random sample, each is a Bernoulli trial that succeeds with probability $p$, the model's true accuracy, and the count of correct rows is binomial. The observed accuracy $\hat p$ then has the *binomial standard error*

$$
\mathrm{SE}(\hat p) = \sqrt{\frac{p(1-p)}{n}},
$$

estimated by substituting $\hat p$ for $p$, and a 95% interval is approximately $\hat p \pm 1.96\,\mathrm{SE}$. The standard error depends only on the accuracy, through $p(1-p)$, and on the number of test rows, through $1/\sqrt{n}$.

At 98% accuracy on 360 images the standard error is 0.0070, so the interval extends about 1.4 points either way. That is wider than the gap between the top two models and not much narrower than the gap between the top and the bottom. Nothing in the single split distinguishes "the SVM is better than logistic regression" from "these 360 images happened to suit the SVM".

### Repeated splits measure the pool, not the training variation


The common response to a noisy split is to repeat it and report the mean and standard deviation. The next block does this for 200 stratified splits. Beside the observed standard deviation it prints three reference quantities, and it computes cross-validated predictions (`cv_correct`) that will serve as a control.

```python
sp = ev.split_scores(X, y, splits=200)
cvc = ev.cv_correct(X, y)
for name, acc in sp["accuracy"].items():
    p = acc.mean()
    print(f"{name:9s} SD {acc.std(ddof=1):.4f}  "
          f"binomial {ev.binomial_se(p, 360):.4f}  "
          f"pool {ev.pool_se(p, 360, len(y)):.4f}  "
          f"fixed model {ev.subset_sd(cvc[name], 360):.4f}")
```

```text
logistic  SD 0.0079  binomial 0.0089  pool 0.0079  fixed model 0.0084
RBF SVM   SD 0.0069  binomial 0.0070  pool 0.0063  fixed model 0.0063
3-NN      SD 0.0052  binomial 0.0058  pool 0.0052  fixed model 0.0051
```

The columns are the standard deviation of accuracy over the 200 splits; the binomial standard error of one 360-image test set; the same with a finite-population correction; and a fixed-model control. For the SVM the spread over splits, 0.0069, is close to the binomial standard error of 0.0070. But it is slightly *below* the binomial figure for every model, the first sign that the repetition measures something narrower than it appears to.

#### The finite-population correction

The binomial formula assumes each test set is a fresh sample from an unlimited population. Two hundred splits of one pool of 1,797 images instead draw 360-image subsets of the same images, without replacement. When $n$ items are drawn without replacement from a population of $N$, the variance of the sample mean shrinks by the *finite-population correction*

$$
\frac{N - n}{N - 1}.
$$

At $n = N$ the variance is zero. Applied to the SVM, the correction predicts a spread of 0.0063, and for all three models the corrected `pool` column sits close to the observed standard deviation.

#### A control that holds the model fixed

Each repeated split changes both the test set and the training set, so its spread could reflect test-set sampling or the model changing as it is retrained. The last column separates the two. It uses *out-of-fold predictions* from 10-fold cross-validation: the data are divided into ten folds, each predicted by a model trained on the other nine, so every image gets exactly one prediction from a model that did not see it. Each image's right-or-wrong outcome is then held fixed, and random 360-image subsets of those outcomes are scored. Because the outcomes never change, the model never changes; only the choice of test images varies.

That spread, 0.0063 for the SVM, is pure test-set noise with the training set held still, and it accounts for most of the repeated-split spread. The share of variance left over for retraining on different data is -15% for logistic regression, 15% for the SVM and 7% for 3-NN. A negative share means the control alone is already a little wider than the measured spread; both are estimates from finitely many draws.

So repeating the split re-measures the test-set noise of *this* pool, slightly understated, and almost none of the variation from training on different data. It does not tell you how the score would move on a new sample of digits; for that, the binomial standard error of one test set is the better answer, because it treats the test set as a sample from the population rather than a subset of a fixed pool. What the repetition does show plainly is the ranking's instability: the SVM and 3-NN trade places in 14% of the 200 splits, as the figure below shows.

One test set's 95% interval is about +-0.014, wider than the gap between the SVM and 3-NN, which swap places in 14% of splits.](ml101-f0-spread.png){alt="Three overlapping clouds of dots for three classifiers, each about two points tall, with error bars of the same height."}

### Comparing models on the same rows


The error bars so far treat each model's score as an independent measurement. They are not. Two good classifiers fail on mostly the same hard images, so on a shared test set their errors are positively correlated, and the variance of a difference between positively correlated quantities is smaller than the sum of their variances. A *paired comparison* exploits this by scoring both models on the same rows and analysing per-row differences.

#### Only disagreements carry information

On each row the two models are both right, both wrong, or split. Rows where they agree contribute nothing to the difference in accuracy; only the *discordant* rows carry information. Let $b$ be the number of rows only model A gets right and $c$ the number only model B gets right. If the models are equally good, each discordant row is equally likely to fall either way, so $b$ is binomial with $b + c$ trials and probability one half. *McNemar's test* tests that hypothesis; its exact form, used here, is a two-sided binomial test on those counts.

The same reasoning explains why pairing shrinks the standard error. Let the per-row difference $D_i$ be $+1$ if only A is right, $-1$ if only B is right, and $0$ otherwise. With a fraction $d$ of rows discordant and mean difference $\delta$,

$$
\mathrm{Var}(D_i) = d - \delta^2 \approx d.
$$

The noise in the difference is governed by the disagreement rate, not by the two models' separate error variances.

To use every image, the comparison uses the 10-fold out-of-fold predictions, on the same folds for all three models, so each image is scored once by each model. The block compares 3-NN with the SVM and prints the discordant counts, the unpaired and paired standard errors of the difference, McNemar's p-value, and the rows a comparison of this size would need.

```python
r = ev.paired(cvc["3-NN"], cvc["RBF SVM"])
print(f"3-NN - SVM on all {r['n']:,} images: {r['difference']:+.4f}")
print(f"right only for 3-NN: {r['only_a']}   only for SVM: {r['only_b']}")
print(f"SE unpaired {r['unpaired_se']:.4f}   paired {r['paired_se']:.4f}"
      f"   McNemar p = {r['p_value']:.3f}")
print(f"rows needed: {ev.rows_needed(abs(r['difference']), r['discordance']):,}")
```

```text
3-NN - SVM on all 1,797 images: +0.0061
right only for 3-NN: 20   only for SVM: 9
SE unpaired 0.0040   paired 0.0030   McNemar p = 0.061
rows needed: 3,381
```

On 1,797 images, 3-NN is right on 20 that the SVM gets wrong, and the SVM on 9 that 3-NN gets wrong; on every other image they agree. Pairing takes the standard error of the difference from 0.0040 to 0.0030, because the per-row difference is zero almost everywhere. The gap is 0.6 points in favour of 3-NN with McNemar p = 0.06: suggestive, not settled, on every image the dataset has.

#### How many rows a comparison needs

A *power calculation* asks how many rows would settle it: given a true difference $\delta$ and disagreement rate $d$, the number of rows $n$ at which a test at level $\alpha$ detects the difference with probability $1 - \beta$, the test's *power*. Under the normal approximation to McNemar's test, with $d$ treated as known,

$$
n \approx \frac{\left(z_{1-\alpha/2} + z_{1-\beta}\right)^2 d}{\delta^2},
$$

where $z_q$ is the $q$ quantile of the standard normal. More disagreement means a noisier difference and more rows; halving the gap quadruples them.

With 1.6% of images in disagreement, detecting a 0.6-point difference at the 5% level with 80% power takes about 3,381 images, 1.9 times the dataset. The figure below plots the rows needed against the gap, with the measured comparison marked against the dataset's size.

![The measured gap, 0.6% with 1.6% of rows in disagreement, needs 3,381 rows. The whole dataset is 1,797.](ml101-f1-needed.png){alt="Three falling curves on a log scale; a dot for the measured 3-NN versus SVM gap sits above a dashed line marking the size of the dataset."}

Not every comparison here is out of reach. The SVM's 1.5-point lead over logistic regression is decisive (p < 0.001). Some comparisons this dataset can answer; the one at the top of the leaderboard is not among them. The table below collects the three pairwise comparisons.

![Pairing cuts the standard error because two good models fail on mostly the same images. It is still not enough to separate the top two.](ml101-f2-table.png){alt="A three-row table of pairwise comparisons with their disagreement counts, standard errors and p-values."}

Pairing tells us how noisy a comparison is on fixed rows. It leaves open what the repeated splits also failed to answer: how much the score depends on the particular training data. Section 2.1 takes this up by asking what a cross-validation estimate is an estimate of. Before that, Section 1.2 turns to the opposite case: two models whose scores do not differ at all, and what the discordant rows counted here say about them.

## Same Accuracy, Different Answers

<!-- source: ml-20-rashomon; hero: ml120-hero.png -->


Section 1.1 above asked when a difference in test scores means a difference in models. This section asks the converse. When two models have the same test score, are they the same model for practical purposes? (Section 14.5 shows a test score that cannot tell a shortcut from the task; the question here is more modest.) Model selection usually acts as if they were, on the strength of a sentence rarely said aloud: *two models with the same accuracy make the same predictions*, so of two models within noise of each other, either will do. Practitioners rely on it when they break a tie by whichever model trained first, when they retrain with a new seed and ship the result because the accuracy held, and when they swap one library for another at equal score. If it is false, the choice between tied models decides which answer a particular person receives, and nothing in the evaluation records that a choice was made.

This section measures the sentence on a simulated task where the best possible classifier is wrong on more than a quarter of the rows, and on the breast-cancer data, where errors are rare. It first trains one network five times with different seeds and counts how often the copies disagree. It then derives the bounds that relate disagreement to accuracy, which explain both why accuracy cannot see the disagreement and when the disagreement must be small. It compares different model families on the same footing, turns to the easy case, and ends with what to do about rows on which equally good models disagree.

### Many models fit the data equally well


Breiman called the phenomenon the *Rashomon effect*, after the film in which witnesses give equally plausible and incompatible accounts of the same event: many different models fit the same data equally well. Section 7.1 met it in the structure of a single decision tree, which changed when the rows were resampled. Here it is measured where it matters most, in the predictions.

The task is the one used in Section 5.1: two overlapping Gaussian classes in ten dimensions with unequal covariance matrices. Because the true densities are known, the *Bayes rule*, which assigns each row to the class with the higher true posterior probability, can be computed exactly. No classifier can have a lower expected error rate than the Bayes rule, and its error rate, the *Bayes error*, is the irreducible error of the task. Here the Bayes rule errs on 27.6% of the 5,000 test rows. Section 5.1 quotes 0.268, its error on that section's larger 20,000-row test set; the two differ only by sampling. The models are trained on 2,000 rows.

The first experiment trains the same small neural network, scikit-learn's MLPClassifier with one hidden layer of 64 units, five times, changing nothing but the random seed. The seed sets the initial weights and the order in which training examples are visited. The code prints each network's test accuracy, the largest disagreement between any two of the five, and the share of test rows that receive both labels from some seed.

```python
from standarderror.ml import reading as rd

r = rd.rashomon(task="gaussian")     # episode 4's task, 2,000 rows
f = r["families"]["MLP seed"]         # same network, seeds 0-4
print("accuracy by seed: " + " ".join(f"{a:.3f}" for a in f["accuracy"]))
print(f"largest disagreement between two seeds: {f['max_pair']:.1%}")
print(f"rows given both labels by some seed:    {f['ambiguity']:.1%}")
```

```text
accuracy by seed: 0.678 0.673 0.680 0.677 0.670
largest disagreement between two seeds: 22.5%
rows given both labels by some seed:    43.0%
```

The *disagreement* between two models is the share of rows on which their predicted labels differ: the share of discordant rows, in the language of Section 1.1 above. The last quantity, the share of rows on which the set of models does not agree unanimously, is what Marx, Calmon and Ustun call *ambiguity*.

The accuracies span 0.010, a single point. By any significance test they are the same model. Yet two of them disagree on 22.5% of the rows, and across the five, 43% of test rows receive both labels from some seed. For more than two in five cases, which answer a person gets depends on a random number chosen at training time. The figure below sets the spread in accuracy beside the disagreement for each group of models.

![Five networks differing only in their seed span 0.010 in accuracy and disagree on up to 22.5% of rows. Numbers in the figure are the series' episode numbers; Appendix B maps them to sections.](ml120-f0-bars.png){alt="Paired horizontal bars for six groups: on the hard task, the disagreement bars dwarf the accuracy-spread bars; on breast cancer both are small."}

### Why accuracy cannot see the disagreement


Accuracy counts how many rows a model gets right, not which. For a two-class problem, two models disagree on a row exactly when one of them is right and the other wrong. Let the error rates be $e_1$ and $e_2$, and let $d$ be the disagreement, the same quantity as the disagreement rate $d$ in Section 1.1's power calculation. Each row on which only model 1 is wrong counts towards $e_1$ and towards $d$; each row on which only model 2 is wrong counts towards $e_2$ and towards $d$; rows on which both are wrong count towards both error rates and not towards $d$. It follows that

$$
|e_1 - e_2| \;\le\; d \;\le\; e_1 + e_2 .
$$

The lower bound is reached when one model's mistakes are a subset of the other's, and the upper bound when their mistakes never overlap. Equal accuracy pins down only the lower bound, which falls to zero. The upper bound is set by how often the models are wrong.

Here each network is wrong on about a third of the rows, so two of them could in principle disagree on two-thirds. They use a third of that room. Their predicted probabilities show how differently they see the same row. The scatter plot below puts one seed's predicted probability against another's for every test row. On 5.1% of rows the two probabilities differ by 0.5 or more: one network near 0.2 where the other is near 0.7 or higher. Both networks are equally accurate; they have drawn different decision boundaries through a region where the data cannot decide between them, because there the two classes overlap and the training rows are consistent with either boundary.

![The off-diagonal quadrants hold the 19.5% of rows on which the two networks disagree. On 5.1% of all rows their probabilities differ by 0.5 or more.](ml120-f1-scatter.png){alt="A wide cloud of points around the diagonal, with many points in the off-diagonal quadrants where one network says above 0.5 and the other below."}

### Different model families disagree too


The effect is not peculiar to the seeds of one network. Fifteen models were trained on the same data: logistic regression, *quadratic discriminant analysis* (QDA, which models each class as a Gaussian with its own covariance matrix, the form the simulated classes actually have), a support vector machine, gradient boosting, a 25-nearest-neighbour classifier, and five seeds each of a random forest and the network. The code prints the four most accurate and the disagreement among those within one point of the best.

```python
for k, v in sorted(r["accuracy"].items(), key=lambda kv: -kv[1])[:4]:
    print(f"{k:16s} {v:.3f}")
g = r["good"]
print(f"within 1 point of best: {g['models']}, disagree on "
      f"{g['max_pair']:.1%}")
```

```text
QDA              0.716
SVM              0.714
MLP seed 2       0.680
MLP seed 0       0.678
within 1 point of best: ['QDA', 'SVM'], disagree on 9.4%
```

The two best models, QDA and the SVM, differ by 0.002 in accuracy and disagree on 9.4% of rows. Forests trained with different seeds disagree less, 5.3% at most, presumably because averaging 300 trees damps the effect of the seed. That is the remedy Section 7.1 pointed to for a single tree's instability, though that section did not measure it.

### When errors are rare, there is no room to disagree


The bound also says when this does not matter. On the breast-cancer data, with one stratified half split, good models are wrong on two or three tumours in a hundred.

```python
b = rd.rashomon(task="breast cancer")
g = b["good"]
print(f"{len(g['models'])} models within 1 point of {b['best']:.3f}; "
      f"largest disagreement {g['max_pair']:.1%}, "
      f"rows with both labels {g['ambiguity']:.1%}")
```

```text
6 models within 1 point of 0.979; largest disagreement 1.4%, rows with both labels 1.4%
```

With error rates that small, the upper bound $e_1 + e_2$ is small too. When both models are almost always right they must almost always agree, and here 6 models within a point of the best disagree on at most 1.4% of tumours.

So the sentence "same accuracy, same predictions" is a statement about easy problems. On hard ones, such as credit default, hospital readmission or customer churn, or anything else with a large irreducible error, models of equal accuracy are different models, and the choice between them is a choice about *who* gets which answer. Marx, Calmon and Ustun call this *predictive multiplicity*. D'Amour and colleagues call the broader condition *underspecification*: the training procedure and the test score jointly fail to pin down the predictions, and something arbitrary, a seed, an architecture or a library default, fills the gap. The table below collects the measurements.

### What to do with a disputed row


Disagreement among equally good models is information, not only a nuisance. A row on which five seeds split is a row on which the data do not determine the answer, and the people behind those rows deserve to know that their case is close. Three responses follow.

**Measure it.** Train a handful of seeds or a handful of near-equal models, and report the share of rows on which they disagree alongside the accuracy. Here that share, 43% of rows for five seeds, says far more about the reliability of an individual prediction than the accuracy's spread of 0.010.

**Average.** An ensemble of the near-equal models gives one prediction that no longer depends on which seed was drawn. On the disputed rows its probabilities move towards the middle, which is the truthful position.

**Escalate.** For decisions about individuals, route the disputed rows to a slower process, such as a second model, a human review or a request for more information, instead of letting a random number decide.

What does not work is picking one model by a tie-break on the test score, or by whichever happened to be trained first. The models are tied within noise, and whichever one is picked, a different fifth of the people get the other answer, and nobody downstream can tell which fifth. The methods for reading a model in Part IV describe one fitted model, and this section has shown that on hard problems the fitted model is itself partly an accident of training.

Both sections of this chapter have taken the fitted model as given and asked what its test score can say about it. Chapter 2 asks what a cross-validated score says, and about which model.

## In practice

### Report the noise in a score

- **Put an error bar on every test score.** Compute $\sqrt{\hat p(1-\hat p)/n}$ for your test set and report the 95% interval with the score. If it is wider than the gap you are reporting, say so.
- **Check that test rows are independent.** If several rows come from one writer, user, session or document, the binomial interval is too narrow; Section 2.4 measures what happens when rows from the same people are treated as new data.
- **Do not use repeated random splits as a measure of generalisation uncertainty.** On one pool they mostly re-measure that pool's test-set noise. Use them to see how often a ranking flips, not to bound performance on new data.

### Compare models on the same rows

- **Pair the comparison.** Score both models on identical test rows or identical out-of-fold predictions, count the rows where only one is right, and use McNemar's exact test.
- **Do a power calculation before claiming an improvement.** If the rows-needed formula asks for more rows than you have, record the gap as not resolved on this data.

### When scores tie

- **Report disagreement with accuracy.** Retrain with several seeds, or fit several near-equal models, and report the largest pairwise disagreement and the share of rows that receive both labels.
- **Use the bounds to judge when it matters.** If the models' error rates are small, disagreement must be small too. If they are large, the bound leaves room for substantial disagreement; measure it.
- **Do not break ties by test score or by accident.** Among models within noise of each other, the choice is a choice of who gets which answer; make it deliberately or avoid it.
- **Average near-equal models where a single prediction is needed.** The ensemble no longer depends on one seed, and its probabilities on disputed rows sit nearer the middle.
- **Flag disputed rows in decisions about individuals.** Send them to review, a second model or a request for more information.

## Limits of the evidence

### Error bars and paired comparisons (Section 1.1)

- **The binomial error bar assumes independent test rows.** If test rows share a source, such as several digits from one writer, several frames of one video or several sentences of one document, the effective sample is smaller and the error bar wider. The same caveat applies to any interval computed as if the rows were independent, such as the coverage of a prediction interval.
- **The pool-corrected spread is not wrong; it is a different quantity.** If the question is how much this dataset's split could move the score, the repeated splits answer it. If the question is how the model would do on new data, they understate the uncertainty and say almost nothing about the training-set component.
- **The rows-needed formula is an approximation.** It is the normal approximation to McNemar's test with the disagreement rate taken as known. At small disagreement counts it is optimistic; it is for planning, not testing.
- **Cross-validated predictions are not quite independent either.** Each image is predicted by a model trained on 90% of the others, and those models overlap. Dietterich's 1998 comparison of tests is the standard reference for what that does to the *type I error*, the rate of declaring a difference where there is none; McNemar's test on a single split is the conservative choice it recommends. Section 2.2 returns to this for t-tests on cross-validation folds.

### Disagreement among equal models (Section 1.2)

- **Ensembling reduces disagreement but does not resolve it.** Averaging the five networks would give one set of predictions that changes less with any one seed, as the forests show. It does not choose between the boundaries; it blurs them. On a disputed row the members' probabilities straddle 0.5, so their average is closer to 0.5 than the more confident of them, which is honest.
- **One hard task, simulated.** The networks are small, with light regularisation and at most 1,500 training iterations. Larger networks, more data or stronger regularisation would all be expected to change the amount of disagreement; none was tried here, and none can remove the bound, which is arithmetic.
- **Disagreement is not error.** On a row where two models disagree, one of them is right. The point is not that both are bad but that the test score cannot say which to trust on those rows, and the person affected cannot either.
- **The one-point tolerance is a choice.** With a tolerance of zero, no two models qualify; with five points, more would, and the largest disagreement among them could only grow or stay the same. One point is roughly the noise in an accuracy measured on 5,000 rows.

## Key points

1. A test accuracy is a proportion with standard error $\sqrt{p(1-p)/n}$. On 360 images at 98%, the 95% interval is about ±1.4 points.
2. Repeated random splits of one dataset reproduce that spread with a finite-population correction. They measure the pool's test-set noise, not training-set variation and not the spread on new data.
3. Compare models on the same rows. Only disagreements count, and pairing shrinks the standard error of a difference (0.0040 to 0.0030 here).
4. 3-NN beats the RBF SVM on digits by 0.6 points with p = 0.06. Settling it would take about 3,381 images; the dataset has 1,797. Before reporting an improvement, compute how many test rows it would take to detect it; if the answer is more than you have, the improvement is not yet a result.
5. Accuracy says how many rows a model gets right, not which. Two models can disagree on as many rows as the sum of their error rates.
6. On a task where the best possible rule errs on about 28% of test rows, five networks differing only in seed spanned 0.010 in accuracy and disagreed on up to 22.5% of rows; 43% of rows got both labels from some seed. The two best model families, 0.002 apart in accuracy, disagreed on 9.4% of rows.
7. On breast cancer, with errors near 2%, near-equal models disagreed on 1.4%: rare errors leave no room.
8. On hard problems, report how much near-equal models disagree, and for decisions about individuals, consider averaging them or flagging the disputed rows.

## Exercises

1. Take the last model comparison you reported and redo it as a paired comparison: the same test rows, a count of the rows where only one model was right, and McNemar's p-value.
2. Plug the disagreement rate and the gap from Exercise 1 into the rows-needed formula. If the answer is larger than your test set, write the gap down as "not resolved on this data" and keep the comparison open.
3. Check whether your test rows are independent. If they share writers, users, sessions or documents, explain why the binomial error bar is then a floor rather than an estimate.
4. Explain in words why pairing reduces the standard error of a difference most when the two models make almost the same mistakes.
5. Retrain your model five times with different seeds, changing nothing else, and score each on your test set. Count the test rows on which at least two of the five disagree, and the largest disagreement between any pair. If the count is more than a few percent, look at who those rows are: they are the cases where your model's answer is an accident of training, and they are often the cases where the decision matters most.
6. Using the bounds in Section 1.2, explain why two models that are each right on almost every row cannot disagree much, while two models that are each wrong on a third of the rows can disagree on many.
7. A colleague proposes to choose between two models whose accuracies differ by less than the noise by picking the higher one. Describe what you would report instead, and what you would do about the rows on which they disagree.

## Further reading

- Alpaydin and Kaynak (1998), UCI Machine Learning Repository: the source of the handwritten digits data used in Section 1.1.
- McNemar, "Note on the sampling error of the difference between correlated proportions or percentages", *Psychometrika* (1947): the original paired test on discordant counts.
- Dietterich, "Approximate statistical tests for comparing supervised classification learning algorithms", *Neural Computation* (1998): compares tests for classifier differences and warns against resampled t-tests.
- Breiman, "Statistical modeling: the two cultures", *Statistical Science* (2001): introduces the Rashomon effect, the multiplicity of models that fit equally well.
- Marx, Calmon and Ustun, "Predictive multiplicity in classification", *ICML* (2020): defines ambiguity and related measures of how often near-optimal models disagree.
- D'Amour et al., "Underspecification presents challenges for credibility in modern machine learning", *JMLR* (2022): shows that training pipelines with equal held-out scores can yield models that behave differently, and why that matters.
