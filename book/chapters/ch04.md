# The Optimism of Search

Almost no reported score comes from a model that was fixed before any score was seen. Hyperparameters are tuned, model families are compared, feature sets are tried, a fold split or a subgroup is preferred, and the number that reaches the report is the score of whatever won. Each comparison is reasonable, and cross-validation appears to protect it: the scores come from rows the model was not trained on. This chapter measures what that protection is worth once a score has been used to choose. A practitioner meets the question in every tuning report, every table of tuned models and every result at the end of an exploratory analysis, and the answer decides whether the reported number describes the model or the luck of the search that found it.

Chapter 3 ended with an analyst who chose features by their score on a holdout and was rewarded with a holdout score above that of the true model. This chapter shows that the same thing happens when the choosing is done on cross-validation folds, by the most routine procedures in the field. Each section tests one sentence:

- Section 4.1: *the best cross-validated score estimates how well the tuned model will do.*
- Section 4.2: *if every choice in an analysis is defensible, so is its result.*

The two sections widen the search step by step. Section 4.1 isolates one search whose options are written down: a grid over the two hyperparameters of a support vector machine, run on 200 rows. It defines the *optimism* of a search, the best cross-validated score minus the true accuracy of the model it selects, and shows that it grows with the number of configurations compared. It explains the growth as a winner's curse, makes it visible on labels that are pure noise, asks what the search bought in true accuracy, and measures the standard repair, nested cross-validation, which runs the whole search inside each outer fold.

Section 4.2 turns to searches nobody writes down. It walks a data set with nothing in it through an honest plan and then five choices, each defensible and each taken because it scored best. The first choice is the feature-selection leak of Section 3.1; the rest are small searches of the kind Section 4.1 measured. On coin-flip labels the walk reported 0.888 for a pipeline that delivered 0.501 on fresh rows. On real data the same walk raised the report slightly and chose a worse model than the plan it replaced, which is the harder case to see.

Both sections arrive at the same conclusion from different directions. A score that was maximised is no longer an estimate of the model that maximised it, however honest each individual score was. The remedies are the same too: put the entire search, every choice included, inside the validation, or score the search's single winner once on data that no choice ever touched, as Section 3.3 showed a test set must be used.

## The Best Cross-Validated Score Is the Search's Best Luck

<!-- source: ml-35-tuning; hero: ml135-hero.png -->


Almost every model in this book was chosen by something: a learning rate, a tree depth, a regularisation strength, a number of components or of clusters. Section 3.3 showed that a holdout consulted to make decisions stops giving an honest score; this section measures the most common decision made on held-out rows of all, the hyperparameter search, where the held-out rows are cross-validation folds. A grid of configurations is cross-validated, the configuration with the best score is kept, and the best score is reported as the estimate of how well the model will do. That last step rests on the sentence under test: *the best cross-validated score estimates how well the tuned model will do*. Practitioners meet it in every tuning report and every table of tuned models. If it is false, the reported score overstates what the model will deliver, by an amount that grows with the size of the search, and a search on data with no signal can report a respectable score.

This section first sets up the search and measures how far the best score sits from the selected model's accuracy on fresh data. It then explains why the best score is biased upwards and makes the bias visible on labels that are pure noise. It next asks what the search actually bought in true accuracy, and finally measures nested cross-validation, the standard repair.

### A grid search and the accuracy of what it chooses


A *hyperparameter* is a setting fixed before a model is fitted rather than learned from the data. A *grid search* fits the model at every combination of candidate values, scores each by $k$-fold cross-validation, and keeps the best. Section 2.1 found that a cross-validation score estimates the average error of a fitting procedure rather than the error of one fitted model. The question here is narrower and has a sharper answer: what happens to the estimate when the best of many scores is kept.

The model is a support vector machine with a radial basis function kernel (RBF SVM). It has two hyperparameters: $C$, which sets how heavily training errors are penalised against the smoothness of the decision boundary, and $\gamma$, which sets how far the influence of a single training point reaches. The data are 200 rows of a simulated two-class task, the one Section 5.1 uses to study learning curves: two Gaussian classes in 10 dimensions with a Bayes error of 0.268. Grids of 1, 4, 16 and 64 configurations, log-spaced in $C$ from 0.1 to 1,000 and in $\gamma$ from 0.001 to 3.2, are each searched by five-fold cross-validation; the one-cell grid is the default, $C = 1$ and $\gamma = 0.1$. The winner is refitted on all 200 rows and scored on 20,000 fresh rows, which gives its *true accuracy* to within a few thousandths. The whole procedure is repeated on twenty training sets, and the code prints the averages of the best cross-validated score, the true accuracy, and a nested estimate explained later in this section.

```python
from standarderror.ml import around

for r in around.tuning_optimism():   # 200 rows, 20 repetitions
    print(f"{r['size']:3d} configurations: best CV {r['best_cv']:.3f}, "
          f"true {r['true']:.3f}, nested {r['nested']:.3f}")
```

```text
  1 configurations: best CV 0.646, true 0.659, nested 0.653
  4 configurations: best CV 0.628, true 0.648, nested 0.633
 16 configurations: best CV 0.660, true 0.643, nested 0.631
 64 configurations: best CV 0.669, true 0.647, nested 0.633
```

With one configuration there is no search, and the cross-validated score of 0.646 sits below the true 0.659. That is the usual direction: each fold's model is trained on four-fifths of the rows, so it is a little worse than the model refitted on all of them, and cross-validation is slightly *pessimistic*. With 64 configurations the best score is 0.669 and the selected model's true accuracy 0.647. Define the *optimism* of the search as the best cross-validated score minus the selected model's true accuracy; at 64 configurations it is 0.023, with a standard error of 0.005 over the twenty repetitions. The estimate has changed sign. The figure below shows the three quantities as the grid grows.

### Why the best of many scores is biased upwards


Each cross-validated score is an estimate with noise, and on 200 rows that noise is several points of accuracy. The search keeps the highest. Among sixteen or sixty-four configurations of similar real quality, the highest score belongs, more often than not, to the configuration whose folds happened to suit it. Its score is high partly because the configuration is good and partly because it was lucky, and only the first part comes with it to new data. This is a selection effect, of the same kind as the winner's curse in auctions: the maximum of several noisy estimates is a biased estimate of the quantity behind the winner, even when each estimate on its own is unbiased. Varma and Simon showed the bias on gene-expression classifiers; Cawley and Talbot named it over-fitting in model selection.

#### Pure noise makes the luck visible

On labels that are coin flips, unrelated to the features, every model's true accuracy is 0.5, so any score above that is luck. The same searches are run on 200 rows of ten standard-normal features with coin-flip labels.

```python
for r in around.tuning_optimism(null=True):   # labels are coin flips
    print(f"{r['size']:3d} configurations: best CV {r['best_cv']:.3f}, "
          f"true {r['true']:.3f}, nested {r['nested']:.3f}")
```

```text
  1 configurations: best CV 0.519, true 0.501, nested 0.524
  4 configurations: best CV 0.552, true 0.500, nested 0.529
 16 configurations: best CV 0.562, true 0.500, nested 0.520
 64 configurations: best CV 0.575, true 0.499, nested 0.524
```

With no search the score is 0.519. With 64 configurations the best score averages 0.575, and the models it picks score 0.499 on fresh rows. A report of "57.5% accuracy, cross-validated" on these data would describe a classifier that knows nothing.

The growth with grid size is informative too. Going from one configuration to four raised the best noise score by 0.033; going from sixteen to sixty-four, four times as many again, raised it by only 0.013. Even for independent draws the expected maximum grows ever more slowly, roughly as the square root of the logarithm of their number, but these scores are not independent either: neighbouring cells of an SVM grid fit nearly the same function and make nearly the same mistakes on the same folds, so they share their luck. The optimism depends on how many genuinely different models a search compares. That suggests that searches across model families, or over many unrelated hyperparameters, would inflate the best score faster than a fine grid over two. The figure below shows the noise searches.

![The best of 64 cross-validated scores averaged 0.575 for models that are right half the time.](ml135-f1-null.png){alt="The best cross-validated score climbs from about 0.52 to 0.575 as the grid grows; the true accuracy stays at 0.5; nested cross-validation stays near 0.52."}

### What the search bought in true accuracy


The search was meant to find a better model, and the true accuracies show whether it did. The best configuration anywhere in the 64-cell grid, trained on the same 200 rows, would have scored 0.668 on fresh data. The search picked one that scored 0.647, 0.021 short, because the noise that inflated the winner's score also misled the choice: the configuration with the luckiest folds need not be the one with the best true accuracy. And the untuned default, with no search at all, scored 0.659, better on average than the tuned model.

The four-cell grid is the odd point in the first figure. Its cells sit at the corners of the range, every one of them worse than the default, so both its best score and its chosen model fall. A search can only choose among the configurations it is given.

None of this is a general verdict against tuning. On this task the default happens to sit near the best region of the grid, and with more rows the scores are less noisy and the search chooses better. It is a verdict against reading the best score as evidence. The 0.023 by which the tuned model's score beat the default's untuned score was luck, and on fresh data the order reversed. The table below collects the optimism for every grid size, on the task and on noise.

Numbers in the figure are the series' episode numbers; Appendix B maps them to sections.](ml135-f2-table.png){alt="An eight-row table: optimism is slightly negative for one or four configurations on the task and positive for 16 and 64; on noise it grows from 0.018 to 0.076."}

### Nested cross-validation evaluates the search as part of the procedure


The standard repair keeps the search out of the estimate. *Nested cross-validation* splits the rows into outer folds. Within each outer training set it runs the whole search, by an inner cross-validation, and scores the chosen configuration on the outer fold, which the search never saw. The search becomes part of the procedure being evaluated, so its luck is evaluated too: a configuration chosen because its inner folds were kind gets no credit for that on the outer fold. Here there are five outer folds.

On the task, nested cross-validation estimated 0.633 for the 64-configuration search, 0.013 below the truth with a standard error of 0.009. That is pessimistic by about as much as plain cross-validation of the untuned model, and for the same reason: every model it scores was trained on a fraction of the rows. On the noise labels it estimated 0.524, against a best score of 0.575 and a truth of 0.499. It is not perfect at 200 rows, but it removed about two-thirds of the optimism.

The price is computation. Each of the five outer folds repeats the full search, so 64 configurations cost five times as many fits. The alternative, when the data allow, is simpler: hold out a test set that the search never touches, and report the selected model's score on it once. Section 3.3 measured what happens to such a test set when it is consulted more than once.

A hyperparameter grid is the tidiest kind of search: its options are written down in advance and can be counted. Section 4.2 turns to the searches that nobody writes down.

## Five Defensible Choices Turned Coin Flips Into 89%

<!-- source: ml-67-forking-paths; hero: ml167-hero.png -->


Chapter 3 and Section 4.1 above each isolated one mistake at a time: fit the selector inside the folds, do not choose by the test set, do not trust the best of many scores. A real analysis rarely makes one mistake. It makes a sequence of choices, each reasonable, each taken after seeing how the last one turned out. The sentence under test is the defence every analyst would offer for such a sequence: *if every choice in an analysis is defensible, so is its result*. A practitioner meets it whenever a final number is the end of an exploratory analysis rather than of a plan written in advance. If it is false, a result can be inflated far beyond anything the data support without any single step being wrong.

This section first builds a data set with nothing in it and walks it through an honest plan followed by five defensible choices, each taken because it scored best. It measures what the reported score becomes and what the resulting pipeline delivers on fresh data. It then repeats the walk on real data, where the damage is smaller and harder to see, and ends with what an honest plan costs.

### The garden of forking paths


Gelman and Loken called the space of choices an analyst could make the *garden of forking paths*. Their point is that an analyst need not try everything, or consciously fish for a result, for the result to depend on which branch the data happened to favour. It is enough that each choice is made after seeing the data, because a different sample would have led to a different branch. The rest of this section measures how far such a walk can go.

### A walk through five choices on pure noise


The data are built to contain nothing: 200 rows, 1,000 features of standard Gaussian noise, and labels by coin flip, so the true accuracy of every model is 50%. One more noise column, by its sign, splits the rows into two subgroups.

The analysis starts with an honest plan, fixed in advance: standardise the features; inside each fold, select the 20 features most associated with the label (by an F-test, which ranks features by how much the class means differ relative to the spread within classes); fit logistic regression; report five-fold cross-validated accuracy. Then five choices are made one after another. Each keeps the previous choices and takes whichever of its options scores best:

1. select the features once on all the rows, because it is simpler;
2. try four model families (logistic regression, an RBF support-vector machine, 15-nearest-neighbours and a random forest);
3. try ten random assignments of rows to folds;
4. try 10, 20 or 50 features;
5. report the subgroup in which the model works better.

Every step is something a careful person has done. The code below runs the walk on one data set and also scores the final pipeline on 5,000 fresh rows drawn the same way.

```python
import numpy as np
from standarderror.ml import course

g = np.random.default_rng(0)
X, y = g.normal(size=(200, 1000)), g.integers(0, 2, 200)    # no signal
Xf, yf = g.normal(size=(5000, 1000)), g.integers(0, 2, 5000)
sub, subf = (g.normal(size=200) > 0) * 1, (g.normal(size=5000) > 0) * 1
w = course._forked(X, y, Xf, yf, sub, subf)
for step, score in zip(course.STEPS, w["reported"]):
    print(f"{step:30s} {score:.3f}")
print("choices:", w["choices"], " fresh rows:", round(w["fresh"], 3))
```

```text
honest plan                    0.445
select features on all rows    0.785
best of four models            0.785
best of ten fold splits        0.790
best of three feature counts   0.790
best of two subgroups          0.781
choices: {'model': 'logistic', 'split': 6, 'k': 20, 'subgroup': 1}  fresh rows: 0.508
```

On this data set the honest plan reports 0.445, below a coin, as a noisy estimate of 50% can. Selecting features on all rows lifts the report to 0.785 at once; the next three choices add a little or nothing; and the pipeline the walk ends with scores 0.508 on fresh rows. The last step lowered the score in this run. That can happen, because the subgroup step picks the better of two halves of the data rather than the better of a half and the whole. The whole-data score is not one of its options, so the better half can still score below it.

### What the walk adds up to


One data set is one draw, so the walk was repeated on 20 such data sets. Averaged over them, the honest plan reported 0.484, as it should. Selecting the features on all rows, the leak measured in Section 3.1, added +0.261 by itself. The mechanism is that the 20 features were chosen because they happened to correlate with the labels of every row, including the rows that later serve as validation folds, so the folds no longer test the model on rows that played no part in building it.

Each later step added a little: +0.007 for the best model, +0.021 for the best fold split, +0.032 for the best feature count and +0.083 for the better subgroup. The final report averaged **0.888**, between 0.781 and 0.957 across the 20 data sets. The pipeline the walk ended with scored 0.501 on 5,000 fresh rows.

![The reported score after each choice, averaged over 20 noise data sets. Reported after five choices: 0.888 on average. Delivered: 0.501.](ml167-f0-walk.png){alt="A line climbing from 0.48 to 0.89 across a plan and five choices, with a band widening around it; a flat line at 0.50 for fresh data."}

#### The optimism is in the sequence, not in any step

No step after the first added more than 0.083, and each has a respectable justification: model choice is what cross-validation is for, the fold split is arbitrary anyway, the number of features is a hyperparameter, and a subgroup effect is a finding. What makes them dangerous is the order. Each was taken because of the score it produced. A cross-validated score is an estimate with noise, and the maximum of several noisy estimates is biased upwards, because the option that wins is disproportionately the one whose noise happened to be favourable; Section 4.1 above measured this winner's curse for hyperparameter tuning. Each step therefore spent a little of the data's ability to tell signal from noise, and the reported score is the maximum of a search nobody wrote down.

This is not new to machine learning. Simmons, Nelson and Simonsohn showed in 2011 that four such freedoms in a psychology experiment can push the false-positive rate from 5% to over 60%. Cawley and Talbot made the machine-learning version of the argument for model selection in 2010.

Which model won depended on the data set: across the 20, the walk chose the SVM 10 times, logistic regression 8 times, the forest once and 15-NN once. On noise there is no right answer for the search to find, so it finds whichever wrong one fits this sample best.

The spread matters as much as the average. In the luckiest of the 20 noise data sets the walk reported 0.957, and in the least lucky 0.781. Both would pass most reviews, and no reviewer could tell from the number alone which kind of data set they were looking at.

### On real data the damage is quieter


The same walk was run on the breast-cancer data, where the signal is strong, using 300 tumours for the analysis and 269 held out as fresh data, over 20 random splits, with subgroups above and below the median texture. Here it looks harmless. The honest plan reported 0.971; the five choices took the report to 0.977, a gain nobody would question.

The held-out tumours tell a different story. On those in the subgroup the walk chose, tumours that played no part in the analysis, the walk's final pipeline scored 0.965, and the honest plan, scored on the same tumours, **0.974**. The search did not merely inflate the report; it chose a worse model than the plan it replaced. Presumably this is because every choice was made on small differences in a small sample, and when every candidate is good those differences are mostly noise, so selecting on them selects on noise.

That is the more common situation, and the harder one to see. On noise a reported 89% is implausible enough to invite a second look. On real data a reported 97.7% is entirely plausible, and only data that played no part in any choice can show that it is not real. The table below sets the two walks side by side.

![The walk on noise and on breast cancer. Each step keeps the previous steps' choices and picks the best option of its own.](ml167-f1-table.png){alt="A table of six rows. On noise the reported score climbs by 0.26, then smaller steps, to 0.888; fresh accuracy is 0.50. On breast cancer the reported score climbs slightly and the chosen pipeline does worse on fresh tumours than the honest plan."}

### An honest plan costs nothing here


The honest plan cost nothing in either setting. Fixed before any score was seen, it delivered 0.974 on the held-out tumours, 0.008 more than the searched pipeline, and on noise its fresh score was 0.505, as close to a coin as its report. A plan written in advance is often described as a constraint that leaves accuracy on the table; here the table was empty, and the search only moved the report away from the truth.

Searching is not always wasted; sometimes a search does find a better model. The way to keep it honest is the one Section 4.1 above measured for tuning. Either run the whole search, every choice included, inside an outer cross-validation loop, so that each outer fold's score comes from a search that never saw that fold, or score the search's single winner once on data held out from all of it, as Section 3.3 showed a test set must be used: once.

Both sections of this chapter concern single results, and Section 22.2 returns to them by rerunning the book's own single-draw verdicts on new seeds. Chapter 5 asks a broader question: how far more data goes, and, in Section 5.3, which of the problems this book measures a larger data set would make go away.

## In practice

### Reporting a tuned or searched result

- **Do not report the best cross-validated score as the tuned model's performance.** Report a nested cross-validation estimate, or the selected model's score on a test set the search never saw, consulted once.
- **Put searches inside the validation.** If several models, settings or feature sets must be compared, run the entire comparison, every choice included, inside an outer cross-validation loop.
- **Keep data that no choice touches.** Set aside a test set before the analysis starts, score the final pipeline on it once, and report that number rather than the search's.
- **Run the search once on shuffled labels.** Rerun the identical search with the labels permuted and record its best score. That is what the search reports when there is nothing to find; if the real best score is not far above it, most of the score is luck.
- **Keep the untuned default in the comparison, judged on data the search never saw.** In Section 4.1 the default did better on fresh data than the tuned model, although its cross-validated score was lower; a search on few rows can choose worse than not searching.

### Counting the search

- **Write the analysis plan before looking at any score**: preprocessing, features, model, validation scheme, metric and any subgroups.
- **Record how many configurations a search compared, and count the choices made after looking.** Each choice, however defensible, is a step in a search, and the reported score is the maximum of that search. The more genuinely different options were tried, the less the best score means; report the count alongside the score.
- **Expect more optimism from broad searches.** Random searches over many hyperparameters and comparisons across model families offer more independent chances than a smooth two-dimensional grid.
- **Distrust plausible numbers as much as implausible ones.** On real data an inflated score looks like a normal one; only untouched data can tell them apart.

## Limits of the evidence

### One tuning search (Section 4.1)

- **Small data on purpose.** At 200 rows the cross-validation noise is large, and so is the optimism. With thousands of rows both shrink, though the optimism still grows with the number of configurations compared.
- **A smooth grid.** Neighbouring configurations of an SVM behave alike, so 64 grid cells are fewer than 64 independent chances. Random search over many hyperparameters, or comparisons across model families, offer more independent chances and more optimism.
- **One model family.** Selecting among different algorithms by their best cross-validated scores adds a second layer of selection on top of this one.
- **Accuracy only.** The same arithmetic applies to any score that is maximised over a search, including AUC and log loss.

### A walk through choices (Section 4.2)

- **A greedy walk.** Each step took the best option given the previous ones. A real analyst explores less systematically and sometimes backtracks, which can add more optimism or less.
- **Pure noise as the main case.** With no signal every gain is spurious, so the walk measures optimism at its largest. The breast-cancer version shows the other end; most problems sit between.
- **Five particular choices.** Others are as common: dropping outliers by residual, transforming the target, choosing the metric. Any choice made after seeing a score belongs on the list.
- **Selection on all rows at step one.** Without that leak the later steps would presumably add less, because each would be judged by honest cross-validation; the search would still inflate the maximum, as Section 4.1 measured for tuning. That variant was not run.

## Key points

1. Cross-validation of one untuned model was slightly pessimistic, by 0.013. The best of 64 cross-validated scores was optimistic by 0.023.
2. On labels that were pure noise, the best of 64 scores averaged 0.575; the selected models scored 0.499 on fresh data.
3. The search's winner scored 0.647 on fresh rows, 0.021 below the best configuration in its grid and below the untuned default's 0.659.
4. Nested cross-validation, which runs the search inside each outer fold, estimated 0.633 against a truth of 0.647 on the task, and 0.524 on noise, where it removed about two-thirds of the optimism.
5. On coin-flip labels, an honest plan reported 0.484; five choices, each taken because it scored best, reported 0.888; the result delivered 0.501.
6. After the first leak, no single step added more than 0.083: the optimism was in the sequence, not in any step. Which model won on noise depended on the data set, because there was no right answer for the search to find.
7. On breast cancer the walk reported 0.977 and delivered 0.965, below the honest plan's 0.974.
8. Write the analysis plan before looking at scores, count the configurations and choices tried, and report a searched result from nested cross-validation or from a test set that no choice ever touched.
