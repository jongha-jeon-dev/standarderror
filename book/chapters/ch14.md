# Importance and Explanation

A model that predicts well invites a second question: what has it learned? Practitioners answer it with a small set of standard tools. A forest offers a feature-importance bar chart by default; permutation importance ranks features by what shuffling them costs; a partial dependence plot draws how the prediction moves with one feature; SHAP values split a single prediction into one contribution per feature. The answers are used to rank features and prune inputs, to argue that risk rises with some measurement, to tell a customer, a clinician or a regulator why a decision came out as it did, and to decide whether a model can be trusted. Each of these tools computes something exact. The trouble, in every case, lies in the gap between what the tool computes and the sentence people use to read it. This chapter takes five such sentences and tests each one on data where the answer is known or can be checked: simulations with a planted truth, the breast-cancer and diabetes data, and the handwritten digits.

The sentences under test are these.

- Section 14.1: *impurity importance ranks the features the forest relies on.*
- Section 14.2: *permutation importance measures how much the model needs the feature.*
- Section 14.3: *a partial dependence plot shows a feature's effect.*
- Section 14.4: *a SHAP value is the unique fair attribution of a prediction to its features.*
- Section 14.5: *the model with the better held-out score has learned the task better.*

The sections build on one another. Section 14.1 starts from the random forests of Chapter 7 and shows that the default importance, computed on the training rows, rewards features with many possible split points, so that useless identifiers can outrank a real effect; it recommends permutation importance on held-out rows instead. Section 14.2 examines that recommendation and finds that permutation importance answers only the narrowest of three questions, how much one fitted model leans on a column. Correlated features divide it between them, and shuffling one of them asks the model about rows that no one has measured. Section 14.3 moves from how much a feature matters to how the prediction depends on it, and meets the same invented rows inside the partial dependence plot; accumulated local effects, which move each row only a little, stay on the data. Section 14.4 moves from averages over a dataset to a single prediction. The uniqueness of Shapley values holds only once a reference has been chosen, and the usual way of filling in missing features builds impossible rows once more. Section 14.5 then asks whether any of this reading is needed when a model is simply accurate. A planted shortcut shows that a held-out score drawn like the training data cannot tell a model that learned the task from one that learned how the data were collected, and that an importance ranking, read with the suspicion the earlier sections teach, can.

Two lessons run through the whole chapter. Every importance score and every explanation answers a narrower or different question than the sentence used to read it, so the question should be stated with the number. And any method that edits one column of a real row, by shuffling it, setting it to a grid value or filling it from a background, asks the model about combinations of values the data never contain, which matters most exactly when features are correlated.

## Impurity Importance Rewards Features With Many Places to Split

<!-- source: ml-12-impurity; hero: ml112-hero.png -->


Section 7.1 showed that a single tree's structure is a property of its sample: refitted on bootstrap resamples, a depth-3 tree changed its root feature half the time while its accuracy held steady. The standard response is to average many trees into a *random forest*, an ensemble of trees each grown on a bootstrap resample of the rows, with a random subset of features considered at each split, whose predictions are averaged. A forest stabilises the predictions and gives up the readable tree. What people read instead is the forest's feature-importance bar chart, and they read it through one sentence: *impurity importance ranks the features the forest relies on.* A practitioner meets this sentence every time `feature_importances_` is plotted and the top bars are reported as the drivers of the outcome, or the bottom ones are dropped as useless. If the ranking reflects how many values a feature takes rather than how much it matters, those reports promote identifiers and demote real effects.

This section defines the default measure, reproduces a null experiment in which it ranks five useless features anyway, then gives one feature a real effect and finds it ranked last, comparing permutation importance on fresh rows throughout. It closes on real data with strong signals, where the bias barely shows.

### How impurity importance is computed


The importance most libraries draw by default, including scikit-learn's `feature_importances_`, is *mean decrease in impurity* (MDI). Recall from Section 7.1 that a tree chooses each split to maximise the reduction in the Gini impurity of the node, weighted by the rows it holds. MDI adds up those reductions by feature: for each feature, the total reduction in Gini impurity from every split on it, across every tree, normalised so that the importances of all features sum to one. Written out, for feature $j$ in a forest of $T$ trees,

$$
\mathrm{MDI}_j \propto \frac{1}{T}\sum_{t=1}^{T}\ \sum_{v \in t:\ v \text{ splits on } j} w_v\, \Delta G_v ,
$$

where $w_v$ is the share of training rows reaching node $v$ and $\Delta G_v$ is the decrease in impurity its split achieves. (scikit-learn normalises each tree's importances to sum to one before averaging over trees, so the proportionality is exact only up to that per-tree weighting.)

Two facts about this construction matter. First, it is computed on the training data, the rows the trees were grown on, so a split that fits noise in those rows earns credit as readily as one that captures a real pattern. Second, a feature gets credit every time it is chosen for a split, and a feature with more possible split points has more chances to be chosen, by luck as much as by merit. A binary feature offers one threshold; a continuous feature offers one between almost every pair of neighbouring values. The best of many candidate thresholds is larger by chance alone the more candidates there are.

### With no signal, importance follows the number of distinct values


#### The null experiment

Strobl and colleagues built the cleanest test of this in 2007. Five features differ *only* in how many distinct values they take: a binary feature, categorical features with 4, 10 and 20 levels coded as integers, and a continuous standard-normal feature. The label is a fair coin, independent of all of them, so every feature's true importance is zero. Each dataset has 500 training rows, and there are 20 datasets. A scikit-learn random forest with fully grown trees is fitted to each.

Alongside MDI the code reports *permutation importance* computed on 2,000 fresh test rows from the same simulation. Permutation importance, introduced by Breiman with random forests, asks a different question on different rows: how much does the model's score fall when one feature's column is randomly shuffled, breaking its relation to the label while leaving its distribution intact? For feature $j$, with $s$ the model's accuracy on the test rows and $s_{j}^{(k)}$ its accuracy after the $k$-th of $K$ shuffles of column $j$,

$$
\mathrm{PI}_j = s - \frac{1}{K}\sum_{k=1}^{K} s_{j}^{(k)} .
$$

The block prints both measures, averaged over the 20 datasets.

```python
from standarderror.ml import trees as tr

# 20 datasets of 500 rows; y is a coin flip, independent of all five
r = tr.importance_null(signal=0.0)
for n, a, b in zip(r["names"], r["mdi"], r["perm"]):
    print(f"{n:11s} MDI {a:.3f}   permutation on new data {b:+.4f}")
```

```text
binary      MDI 0.046   permutation on new data -0.0008
4 levels    MDI 0.098   permutation on new data +0.0008
10 levels   MDI 0.184   permutation on new data +0.0003
20 levels   MDI 0.255   permutation on new data +0.0014
continuous  MDI 0.417   permutation on new data -0.0013
```

#### Reading the result

MDI climbs with the number of distinct values, from 0.046 for the binary feature to 0.417 for the continuous one, in perfect order. The order holds in each of the 20 datasets separately. Fully grown trees keep splitting until their leaves are pure, which on coin-flip labels means splitting down to leaves of one or a few rows. At every node the feature with the most thresholds to choose from is the one most likely to find a split that happens to separate a few heads from a few tails. All of that is memorised noise, and MDI counts every such split as importance.

Permutation importance on new rows sees none of it. For every feature here the answer is zero to within one *standard error* of its mean over the 20 datasets: the noise splits memorised on the training rows do not transfer to new rows. The figure below shows the MDI shares, with and without a signal on the binary feature.

![With no signal anywhere, the continuous feature gets 42% of the importance and the binary one 5%. Giving the binary feature a real effect moves its share to 5%, still last.](ml112-f0-mdi.png){alt="Two sets of bars rising left to right from the binary feature to the continuous one, nearly identical whether or not the binary feature carries signal."}

### A real effect, ranked last


#### Giving one feature a signal

Nobody acts on the ranking of five useless features, so the experiment gives one of them an effect. With the binary feature on, the probability of the positive class is 0.6; with it off, 0.4. The other four features still carry nothing.

The code runs this setting twice, once with fully grown trees and once with a minimum of 20 rows per leaf. For each it prints the mean MDI shares in the same order as before, and how often each method ranks the binary feature first, and MDI ranks it last.

```python
# now P(y = 1) is 0.4 or 0.6 depending on the binary feature
for leaf in (1, 20):
    r = tr.importance_null(signal=0.2, leaf=leaf)
    print(f"leaves >= {leaf:2d}: MDI " +
          " ".join(f"{v:.3f}" for v in r["mdi"]) +
          f"  binary first: MDI {r['mdi_top_binary']:.0%},"
          f" permutation {r['perm_top_binary']:.0%}")
    print(f"{'':14s}binary last by MDI: {r['mdi_last_binary']:.0%}")
```

```text
leaves >=  1: MDI 0.053 0.101 0.187 0.256 0.403  binary first: MDI 0%, permutation 95%
              binary last by MDI: 95%
leaves >= 20: MDI 0.254 0.101 0.152 0.196 0.297  binary first: MDI 25%, permutation 100%
              binary last by MDI: 5%
```

With fully grown trees, MDI never ranks the one informative feature first, and ranks it last in 19 of the 20 datasets. Its share rises only from 0.046 to 0.053, while the continuous noise feature keeps 0.403. Permutation importance on fresh rows ranks it first in 95% of datasets, as the figure below shows.

![Shuffling the binary feature costs 0.036 of accuracy; every other feature costs under 0.004. Permutation importance ranks it first in 95% of datasets, MDI in 0%.](ml112-f1-perm.png){alt="Bars near zero for every feature with no signal; with signal, one tall bar for the binary feature and near-zero bars for the rest."}

#### Why the real effect earns so little credit

The likely reason is the same selection effect as before, compounded by the structure of a tree. A binary feature can be split only once on any path from the root: after the split, every row in each child has the same value of the feature, so it has nothing more to offer below. The continuous feature can be split again and again, at different thresholds, on the same path. In fully grown trees most splits are deep in the tree, among a handful of rows, where they fit noise. MDI adds those up.

#### Larger leaves reduce the bias without removing it

Requiring larger leaves removes the deepest, noisiest splits. With at least 20 rows per leaf the binary feature's share rises to 0.254 and the continuous feature's falls to 0.297. But MDI still ranks the binary feature first in only 25% of datasets. The bias is smaller, not gone. The table below collects the four settings.

![Leaves of at least 20 rows cut the continuous feature's share and lift the binary one, but MDI still prefers the feature with nothing to say.](ml112-f2-table.png){alt="A table of importances for five features under four settings, with two final rows giving how often the binary feature is ranked first and how often it is ranked last."}

#### Where such columns come from in practice

The continuous noise feature here stands in for columns that turn up in real tables all the time: a row identifier, a timestamp, a free-text field hashed to a number, a postcode or a customer number coded as an integer. Each has close to one distinct value per row, so each offers a fully grown tree a split almost anywhere it wants one. None of them should predict anything, and every one of them is a candidate for the top of an impurity-importance chart. When such a column does appear near the top, the chart is not evidence that the model uses it on new data; on new rows, as the permutation results show, it may contribute nothing at all. The check is cheap, and it is the first exercise at the end of this chapter.

### When the bias hides


#### Strong signals crowd out the noise

The bias does not always show. On the breast-cancer data of Section 7.1, with two pure-noise columns added, one standard-normal and one a fair coin, MDI does not promote the noise. On one stratified 70/30 split, the block prints the ranks of the two noise columns under each method, and the number of features with permutation importance of zero or less.

```python
r = tr.importance_real()   # breast cancer + noise columns
print(f"rank of noise (continuous, binary) among {r['features']}:"
      f" MDI {r['mdi_rank']}, permutation {r['perm_rank']}")
print(f"features with permutation importance <= 0: "
      f"{r['perm_nonpositive']}")
```

```text
rank of noise (continuous, binary) among 32: MDI (31, 32), permutation (31, 32)
features with permutation importance <= 0: 5
```

Both methods put the two noise columns at the bottom of the 32. Their impurity shares are 0.2% for the continuous column and 0.03% for the binary one: whatever lucky splits they win add up to a fraction of a percent of the total. A plausible reading, not tested here, is that thirty real features with strong, well-separated signals take the splits near the top of every tree and leave the noise only the deep ones.

#### When the bias matters

So the bias is real and conditional. It matters when real effects are weak relative to the noise; when features differ a lot in how many values they take, such as a binary treatment indicator beside continuous laboratory values, or a postcode with thousands of levels beside a yes/no flag; and when the trees are grown deep. Those are also the settings in which a ranked importance chart is most often used as evidence of what matters, because nothing else stands out.

#### Permutation importance has its own failure

Permutation importance is not a clean replacement, and the breast-cancer run shows its own weakness: 5 of the 32 features have a permutation importance of zero or less. Two are the noise columns; the other 3 are real measurements. This run does not say why those real measurements score nothing. The usual explanation is that each has a strongly correlated neighbour, so that when one is shuffled the trees that split on the other still work. Section 14.2 measures that problem directly.

## Permutation Importance Measures the Model, Not What the Data Need

<!-- source: ml-16-permutation; hero: ml116-hero.png -->


Section 14.1 recommended permutation importance on held-out rows over the impurity importance a forest reports by default, and ended on a warning: even the recommended measure scored three real breast-cancer measurements at zero or below. This section examines the recommended measure itself: shuffle one column of a held-out set, score the model again, and call the drop in performance the feature's importance. The number is usually glossed as *how much the model needs the feature.* Practitioners lean on that sentence whenever they rank features, prune inputs or explain which measurement drives a prediction. If it is false, a ranking can demote a feature that carries real information and change from fit to fit for reasons unrelated to the data.

This section separates three questions that the phrase runs together and shows, on the diabetes data and a random forest, that permutation importance answers only the narrowest. It compares shuffling a feature with refitting without it, adds a copy of the feature to watch the permutation numbers collapse while the refitting numbers hold still, shows that shuffling a correlated feature scores the model on rows that do not exist, and ends by measuring importance for groups of features.

### Three questions behind one phrase


Recall from Section 14.1 that *permutation importance* is computed on a fitted model $\hat f$ and a held-out set: score the model, giving $s$; shuffle column $j$, so that its values are reassigned to rows at random while every other column stays in place; score again, giving $s_{(j)}$; and take the drop $I_j = s - s_{(j)}$, averaged over several shuffles. The score here is the *coefficient of determination*, $R^2 = 1 - \sum_i (y_i - \hat y_i)^2 / \sum_i (y_i - \bar y)^2$, the share of the outcome's variance on the test set that the predictions explain. A shuffle that leaves the predictions unchanged costs nothing.

"How much the model needs the feature" can mean at least three different things:

1. How much does *this fitted model* lean on the column?
2. How much would *a model refitted without the column* lose?
3. How much *information* does the column carry that no other column carries?

Permutation importance answers the first. The model is never retrained; only its inputs are disturbed. The second question is answered by *drop-column importance*: refit the same kind of model on the data without feature $j$ and record the loss in held-out score. The third is a property of the data and does not depend on any one model. The rest of this section shows how far apart the first two answers can be, and why the first can mislead about the third.

### Shuffling a feature and refitting without it disagree


The data are the diabetes data of Efron and colleagues, as bundled with scikit-learn: 442 patients, 10 baseline variables, and a measure of disease progression as the outcome. A random forest of 300 trees with leaves of at least 5 rows is fitted on three 70/30 splits, and each result below is the mean over the three. Permutation importance uses 20 shuffles. Body-mass index, bmi, matters to this forest: shuffling it removes about half of its test $R^2$ of 0.33.

To see how importance behaves when information is duplicated, the experiment adds a second column that copies bmi with a chosen correlation $\rho$: the copy is $\rho \cdot \text{bmi} + \sqrt{1-\rho^2}\cdot\varepsilon$, with the noise $\varepsilon$ scaled to bmi's spread. At $\rho = 1$ it is an exact duplicate. For each setting the code reports four quantities: the permutation importance of bmi, the permutation importance of the copy, the loss from refitting without bmi (keeping the copy), and the loss from refitting without both.

```python
from standarderror.ml import reading as rd

# random forest on diabetes; loss of test R^2, mean of 3 splits
for r in rd.copy_importance(rhos=(None, 0.8, 0.95, 1.0)):
    print(f"{str(r['rho']):>4}  permute bmi {r['feature']:.3f}"
          f"  permute copy {r['copy']:+.3f}"
          f"  refit w/o bmi {r['drop_feature']:.3f}"
          f"  w/o both {r['drop_both']:.3f}")
```

```text
None  permute bmi 0.168  permute copy +0.000  refit w/o bmi 0.043  w/o both 0.043
 0.8  permute bmi 0.162  permute copy -0.001  refit w/o bmi 0.000  w/o both 0.047
0.95  permute bmi 0.115  permute copy +0.009  refit w/o bmi 0.004  w/o both 0.041
 1.0  permute bmi 0.017  permute copy +0.021  refit w/o bmi 0.000  w/o both 0.044
```

Start with the first row, where there is no copy. Shuffling bmi costs 0.168 of test $R^2$. Refitting the forest without bmi costs 0.043, four times less. Both numbers are correct; they answer different questions. The fitted forest has organised its splits around bmi. Wherever a tree splits on bmi, a shuffled value sends the row down a branch meant for a patient of a different build, and the predictions degrade badly. A forest grown from the start without bmi has no such splits to break. It loses only a little, presumably because it finds much of the same information in the other measurements, though which ones carry it was not measured here.

The figure below shows the four quantities side by side for the setting without a copy and the setting with an exact copy.

![Without a copy, shuffling bmi costs 0.168 of test R² and refitting without it 0.043. With an exact copy, shuffling either column costs about 0.02; removing bmi and keeping the copy costs nothing, and removing both costs 0.044.](ml116-f0-copies.png){alt="Grouped bars: without a copy, permuting bmi costs far more than refitting without it; with an exact copy, permuting either column costs little and refitting without both costs as much as refitting without bmi did alone."}

### A copy hides the original


Now consider the last row, with an exact duplicate. The two columns offer identical candidate splits at every node, so which one a tree uses at a given node comes down to tie-breaking. The forest's reliance is presumably divided between them. Shuffle one, and the splits made on the other still route rows correctly; the model has a working spare. Permutation importance falls to 0.017 for bmi and 0.021 for its copy. Their sum, 0.038, is a quarter of what bmi had alone. Permutation importance is therefore not even additive over copies: splitting a feature into two identical columns does not split its importance into two shares that add back to the whole: each shuffle is cushioned by the intact column.

Refitting tells the same story from the other side. Remove bmi and keep its copy, and nothing is lost (0.000). Remove both and the loss is 0.044, the same as removing bmi when there was no copy. That last column is stable across every row of the table. Averaged over the same three splits, the information bmi carries is worth about 0.04 of $R^2$ however it is presented, while the permutation numbers move by a factor of ten.

The intermediate rows show how close a copy must be before the effect appears. At a correlation of 0.8 the forest still leaned almost entirely on the original, and the copy's permutation importance was -0.001, indistinguishable from zero. At 0.95 the copy took 0.009 against bmi's 0.115. Only the exact copy split the importance evenly. A plausible reading is that a noisy copy is a worse version of bmi, and a tree that chooses each split by how much it reduces error will usually prefer the better version.

Real tables are full of near-copies: total cholesterol and LDL, height and weight, a price and the same price in another currency, a date and the age computed from it. A pair that is close enough can divide its permutation importance between its members and push both down a ranking, below features that carry less information but have no partner. Section 14.1's breast-cancer run had three real measurements with permutation importance at or below zero, which is what this effect would produce, though that run did not check the cause.

The table below collects the four settings.

![The last column barely moves: the information in bmi is worth about 0.04 of R² in every setting. The permutation columns move by a factor of ten.](ml116-f2-table.png){alt="A four-row table: test R^2 unchanged by adding a copy; permutation importance of bmi falling from 0.17 to 0.02 as the copy improves; refitting without both near 0.04 throughout."}

### Shuffling a correlated feature invents rows


There is a second problem, and it does not need a copy. Shuffling a column breaks its relationship not only with the outcome, which is the point, but with every other column. When features are correlated, many of the shuffled rows are combinations of values that no real patient has.

The *support* of a distribution is the region where it actually puts its data. A row is *off support* when it lies in a region the data never visit, and a model's prediction there is extrapolation: the training data constrained it nowhere near that point. The code below measures how much of a shuffled test set falls off support for one pair of features, s1 and s2 in the diabetes data, by counting the shuffled rows that lie outside the region holding 99% of real (s1, s2) pairs.

```python
o = rd.off_support(a="s1", b="s2", level=0.99)
print(f"corr(s1, s2) = {o['corr']:.2f}")
print(f"after shuffling s1, {o['outside']:.1%} of rows fall outside "
      f"the region holding 99% of real pairs")
```

```text
corr(s1, s2) = 0.90
after shuffling s1, 29.0% of rows fall outside the region holding 99% of real pairs
```

In the data, s1 and s2 (total cholesterol and LDL) are correlated at 0.90. By construction only 1% of real pairs lie outside the region, so if shuffling produced realistic rows, about 1% of shuffled rows would too. Instead 29% do. A patient with very high total cholesterol and very low LDL is not a patient anyone measured. The forest's prediction for such a row is whatever its nearest leaves say: each tree routes the row by thresholds learned from real patients, and the row can end in a leaf whose value was set by patients who looked quite different. Permutation importance then scores the forest on those predictions, as the figure below shows.

![29% of shuffled rows lie outside the ellipse that holds 99% of real pairs. The model is scored on what it predicts for them.](ml116-f1-offsupport.png){alt="A tight diagonal cloud of real points and a round cloud of shuffled points spreading far off the diagonal."}

Part of what permutation importance measures, then, is how badly the model behaves off the data, which is a property of the model in a region it was never trained on rather than a property of the feature. Hooker, Mentch and Zhou (2021) make this the central objection to permutation-based measures. The remedy they and Strobl and colleagues discuss is *conditional permutation*, which shuffles a feature only among rows with similar values of the other features, so that the shuffled value stays plausible given the rest of the row. It keeps the rows on the data, at the cost of more computation and of more choices, such as how to define "similar".

### Measuring importance for groups of correlated features


If permutation importance answers the narrowest of the three questions, the remedy is to ask a wider one deliberately, and the table already contains the answer to it. Removing bmi and its copy together and refitting cost 0.044 of $R^2$, within a hundredth of the 0.043 that removing bmi cost when it had no copy. Measured as a group, the information is stable: duplicated, nearly duplicated or alone, it is worth the same.

That suggests a working procedure.

1. Cluster the features by correlation. A simple threshold on the absolute correlation is enough to start: features whose correlation exceeds it go in the same group.
2. Report importance for each group, either by permuting all its members together, with the same row permutation applied to every column in the group, or by refitting without the whole group.
3. Within a group, say which member the model happened to lean on, and say that a different fit could lean on another.

Permuting a whole group together should also leave fewer impossible rows behind, since its members move as a block and keep their relationship to one another; what is broken is only their relationship to everything else. That was not measured here.

None of this makes importance a causal statement. A group of features that predicts well may be a proxy for something else entirely, as Section 14.5 shows with a single pixel. Grouping does make the ranking a property of the information in the data rather than of which column the forest's random splits happened to favour. Section 14.3 asks how predictions depend on a feature, and finds the standard picture asking about invented rows in the same way.

## Partial Dependence Asks the Model About Rows That Do Not Exist

<!-- source: ml-17-pdp; hero: ml117-hero.png -->


Section 14.2 measured how much a model leans on a feature, and found the measurement partly made on rows that do not exist. The natural next question is *how* the prediction depends on it, and the standard answer is a picture: the partial dependence plot, introduced by Friedman alongside gradient boosting. It comes with a sentence: *a partial dependence plot shows a feature's effect*, the effect of this feature on the prediction with the others held as they are. Practitioners meet that reading whenever a plot is used to argue that risk rises with age, that price flattens above some size, or that a dose has no effect beyond a threshold. If the plot describes something other than the data, those arguments rest on the model's behaviour in places where it was never trained, and the curve can be flatter, steeper or shaped differently from the true relationship.

This section tests the plot on a simulation where the true effect is known. It defines partial dependence and shows where its construction places the rows it averages over. It compares the plot with accumulated local effects, a method built to stay on the data, as the correlation between two features rises. It then explains, from how a forest predicts, why the partial dependence curve flattens, and ends with a check that tells in advance whether a given plot can be trusted.

### What a partial dependence plot computes


Let $\hat f$ be a fitted model, $x_1$ the feature of interest and $x_C$ the remaining features. The *partial dependence* of the prediction on $x_1$ at a value $v$ is

$$
\mathrm{PD}_1(v) = \frac{1}{n}\sum_{i=1}^{n} \hat f(v,\; x_{i,C}).
$$

In words: for each value $v$ on a grid, set $x_1$ to $v$ in every row of the data, leave every other feature as it is in that row, predict, and average. Plotting $\mathrm{PD}_1(v)$ against $v$ gives the *partial dependence plot* (PDP).

The construction is clean, and it carries a hidden assumption. Setting $x_1$ to $v$ *in every row* creates $n$ artificial rows that pair $v$ with each row's own value of the other features. If $x_1$ is independent of the others, those rows look like draws from the data, and the average estimates the model's response to $x_1$ over the population. If $x_1$ is correlated with another feature, many of the artificial rows pair $v$ with values that never occur alongside it, and the PDP averages the model's predictions there.

### A simulation with a known effect


The simulation makes the true answer explicit. Let $x_1$ be uniform on $[0, 1]$, let $x_2 = x_1 + s\,\varepsilon$ with $\varepsilon$ standard normal, so that $x_2$ is a noisy copy of $x_1$, and let

$$
y = x_1 + 2x_2^2 + 0.1\,\varepsilon',
$$

with $\varepsilon'$ independent standard normal noise. The noise scale $s$ is 0.3, 0.1 or 0.05, and in a fourth setting $x_2$ is an independent uniform variable instead. Each dataset has 1,000 rows, and there are three datasets per setting. The effect of $x_1$, holding $x_2$ fixed, is a straight line of slope 1.

A random forest of 300 trees with leaves of at least 5 rows is fitted to each dataset, and its PDP for $x_1$ is compared with *accumulated local effects* (ALE), described below. The code prints the slope each method finds for $x_1$, averaged over the three datasets, beside the correlation between the two features.

```python
from standarderror.ml import reading as rd

# y = x1 + 2 x2^2; x2 = x1 + noise * N(0, 1) (None: independent)
for r in rd.pdp_vs_ale(noises=(None, 0.3, 0.1, 0.05)):
    if r["model"] == "forest":
        print(f"corr {r['corr']:5.2f}  PDP slope {r['pdp_slope']:.2f}"
```

### Where the plot asks its questions


The scatter of training rows at the highest correlation is a narrow diagonal band: $x_2$ is never far from $x_1$. To compute the PDP at $x_1 = 0.1$, every row has its $x_1$ set to 0.1 and keeps its own $x_2$, which ranges roughly from 0 to 1. The artificial rows form a vertical line through the plane, and most of that line lies far off the band, in regions where the forest saw no data. The figure below draws these lines at $x_1 = 0.1$ and $x_1 = 0.9$.

![To compute the partial dependence at x1 = 0.1, the model is asked about rows with x1 = 0.1 and x2 near 1. No training row looks like that, and the forest's answer there is whatever its nearest leaves say.](ml117-f1-support.png){alt="A narrow diagonal band of training points, and two vertical lines of evaluated points at x1 = 0.1 and 0.9 that run far outside the band."}

A forest's prediction in such a region is not a guess about the function. Each tree routes the row through thresholds learned on the band, and the row ends in a leaf whose value is the average outcome of the training rows that reached it. The prediction is therefore whatever the nearest leaves on the band say. For a row with $x_1 = 0.1$ and $x_2 = 0.9$, the splits on $x_2$ are likely to dominate, because they carry most of the signal ($2x_2^2$ varies more than $x_1$ does over the unit interval), and they send the row to leaves trained on rows with both inputs near 0.9. Its prediction should then be close to what the forest predicts at $x_1 = 0.9$. Individual predictions off the band were not inspected here, but the flattened slope is what that would produce. Averaging many such rows flattens the PDP: the curve says $x_1$ barely matters, because most of the rows it averages over are answered by $x_2$.

### Accumulated local effects stay on the data


ALE, proposed by Apley and Zhu, avoids the problem by never moving a row far. Divide the range of $x_1$ into $K$ bins with edges $z_0 < z_1 < \dots < z_K$, here at quantiles of $x_1$ so that each bin holds about the same number of rows. Within bin $k$, take only the rows whose $x_1$ actually falls in it, move each from the bin's lower edge to its upper edge with its other features unchanged, and average the change in prediction:

$$
\Delta_k = \frac{1}{n_k}\sum_{i:\, x_{i1} \in [z_{k-1}, z_k]} \Big[\hat f(z_k,\, x_{i,C}) - \hat f(z_{k-1},\, x_{i,C})\Big].
$$

The ALE curve at the end of bin $k$ is the running sum $\Delta_1 + \dots + \Delta_k$, conventionally shifted so that its mean is zero. Because each row is moved only across the width of its own bin, the modified rows stay close to the band, and the model is asked only about combinations of values that resemble the data. The cost is that each bin needs enough rows to estimate a local difference.

The code below computes ALE by hand for one dataset at the highest correlation, with 20 quantile bins, and reports how much the prediction rises across the full range of $x_1$.

```python
import numpy as np
from sklearn.ensemble import RandomForestRegressor

X, y = rd.correlated_pair(noise=0.05, seed=0)
f = RandomForestRegressor(300, min_samples_leaf=5, random_state=0)
f.fit(X, y)
edges = np.quantile(X[:, 0], np.linspace(0, 1, 21))   # 20 bins of x1
steps = []
for lo, hi in zip(edges[:-1], edges[1:]):
    rows = X[(X[:, 0] >= lo) & (X[:, 0] <= hi)]        # rows really there
    a, b = rows.copy(), rows.copy()
    a[:, 0], b[:, 0] = lo, hi                         # small move only
    steps.append(np.mean(f.predict(b) - f.predict(a)))
print(f"x1 rises {edges[-1] - edges[0]:.2f}; ALE says the prediction "
      f"rises {sum(steps):.2f}")
```

```text
x1 rises 1.00; ALE says the prediction rises 0.88
```

The true effect is a rise equal to $x_1$'s, 1.00; ALE finds a rise of 0.88, most of it. Where the shortfall comes from was not broken down here; a likely source is the end bins, where a forest's predictions flatten for want of data beyond them. ALE describes the model where it was trained, and on this simulation that is close to the truth.

### The plot is exact, but about the wrong thing


It would be easy to call the PDP wrong. It is not; it is an exact description of the forest's average prediction over a particular set of artificial rows. The problem is that readers take it as a description of the data, and the two come apart precisely when features are correlated. In real tables, with incomes and house prices, ages and years of experience, doses and body weights, correlation is the rule.

The error is not small. Measure each curve's root-mean-square (RMS) distance from the true effect: the square root of the average squared gap between the curve and the truth across the values of the feature. At the highest correlation the PDP's RMS distance from the true effect of $x_1$ is 0.192, against 0.032 for ALE. For $x_2$, whose true effect is the curve $2x_2^2$, it is 0.188 against 0.043. Gradient boosting behaves the same way: its PDP slope for $x_1$ falls to 0.51. Both models predict well on the band, both behave arbitrarily off it, and the PDP reports the arbitrary part. The table below collects the results for both models.

![Both methods are exact descriptions of something. ALE describes the model where the data are; partial dependence describes it everywhere, mostly where they are not.](ml117-f2-table.png){alt="An eight-row table: with independent inputs both methods are accurate; as correlation rises the PDP's slope falls towards 0.3 and its error grows tenfold, while ALE stays close."}

ALE has costs of its own. It needs enough rows per bin to estimate a local difference. It cannot show what the model does off the data, and sometimes that is the question, for instance when a model will be applied to combinations of inputs that were rare in training. And with exactly collinear features no method can separate their effects, because the data contain no rows in which one moves without the other.

### A check before reading the plot


Whether a PDP can be trusted is visible before drawing it. Take the feature and the one it is most correlated with, scatter them, and draw the vertical lines of rows the PDP will build at the lowest and highest grid values. The share of those rows that falls inside the cloud of real data is the share of the curve that describes the data; the rest describes the model somewhere else.

In the simulation at a correlation of 0.985, count a built row as on the data when its $x_2$ is within two noise standard deviations of its $x_1$. Only 17% of the rows built at $x_1 = 0.1$ and $x_1 = 0.9$ are on the data; the rest lie far above the band at 0.1 and far below it at 0.9. Most of the PDP is computed off the data, and its slope is 0.30. At a correlation of 0.69 the band is wide enough to hold 66% of the built rows, and the PDP's slope, 0.78, is correspondingly closer to the truth. The check costs one plot, and it says in advance which of the two curves to believe.

Sections 14.2 and 14.3 have now met the same problem twice, in permutation importance and in partial dependence: a method that edits one column of real rows asks the model about rows that do not exist. Section 14.4 finds it again inside SHAP values, together with a second choice that the method's theorem leaves open.

## A SHAP Value Is an Answer to "Compared With What?"

<!-- source: ml-18-shapley; hero: ml118-hero.png -->


Sections 14.2 and 14.3 dealt with importance and effects averaged over a whole dataset. SHAP values work on one prediction at a time: they split the gap between this prediction and a baseline into one contribution per feature. Their appeal rests on a theorem, and it is usually summarised as *a SHAP value is the unique fair attribution of a prediction to its features.* Practitioners meet that sentence when an explanation is shown to a customer, a clinician or a regulator, and when a feature is reported as "the reason" for a decision. If the word "unique" hides a choice that the analyst made without noticing, then the reason given for a prediction can change when that choice changes, and the person receiving it has no way to know.

This section computes Shapley values exactly, with no sampling or approximation, for a five-feature model of the breast-cancer data. It first defines the Shapley value and what the uniqueness theorem does and does not fix. It verifies the computation on two checks with known answers. It then explains the same predictions against four different reference sets and counts how often the leading feature and the signs of attributions change. It returns to the off-data problem of the previous two sections, which appears here in a second choice, and ends with a procedure for choosing the reference deliberately.

### The Shapley value and what its theorem fixes


Shapley's 1953 result concerns a cooperative game: a set of $p$ players and a *value function* $v$ that assigns a worth $v(S)$ to every *coalition* $S$, every subset of the players. The question is how to share the total $v(\{1,\dots,p\}) - v(\varnothing)$ among the players. The *Shapley value* of player $i$ is its marginal contribution $v(S \cup \{i\}) - v(S)$, averaged over all the orders in which the players could join:

$$
\phi_i = \sum_{S \subseteq \{1,\dots,p\}\setminus\{i\}} \frac{|S|!\,(p-|S|-1)!}{p!}\,\big[v(S\cup\{i\}) - v(S)\big].
$$

Shapley showed that this is the only way of sharing the total that satisfies four properties: *efficiency* (the shares add up to the total), *symmetry* (two players who contribute the same to every coalition get the same share), the *null-player* property (a player who adds nothing to any coalition gets zero) and *additivity* (the shares for the sum of two games are the sums of the shares). Lundberg and Lee brought the result to model explanation in 2017 under the name SHAP, and "the unique fair attribution" has been its selling point since.

The theorem is about a game, and a model is not a game until someone defines what a coalition of features is worth. The usual definition, the *interventional* one, is: fix the coalition's features at this row's values, draw the remaining features from a *background dataset*, and average the model's predictions over the background rows. The empty coalition then has worth equal to the background's mean prediction, called the *base value*, and the full coalition has worth equal to the prediction for this row. Efficiency says the attributions add up to the prediction minus the base value.

The theorem gives a unique answer for a given value function, and the value function depends on the background. The background is the explanation's answer to "compared with what?", and the theorem has nothing to say about it.

### Computing the values exactly


With five features there are only $2^5 = 32$ coalitions, so every term of the formula can be evaluated directly. The code prints the core of the function used in this section.

```text
    for k in range(p + 1):
        for S in itertools.combinations(range(p), k):
            Z = background.copy()
            Z[:, list(S)] = x[list(S)]

            w = (math.factorial(len(S)) * math.factorial(p - len(S) - 1) /
```

The first loop builds the value function. For each coalition `S` it copies the background, overwrites the coalition's columns with the explained row's values, and stores the mean prediction. The second loop applies the Shapley formula: for each feature and each coalition that excludes it, it adds the weighted marginal contribution. The function returns the attributions, the base value `val[()]` and the prediction `val[tuple(range(p))]`.

Two checks confirm the computation. For a linear model $\hat f(x) = \beta_0 + \sum_j \beta_j x_j$ the interventional Shapley values are known in closed form: each feature's attribution is its coefficient times the row's distance from the background mean, $\beta_j(x_j - \bar x_j)$. And for any model, efficiency requires the values to add up to the prediction minus the background's mean prediction.

### Four backgrounds give four explanations


The model is gradient boosting (scikit-learn's HistGradientBoostingClassifier) on five breast-cancer features: worst radius, worst concave points, worst texture, mean smoothness and worst symmetry. - **all training tumours**, the default in most tutorials, which explains why this tumour differs from the average tumour;
- **benign tumours only**, which explains why this one is less benign than a typical benign one;
- **malignant tumours only**;
- **a single row of feature means**, a shortcut many implementations offer because one background row makes every coalition cost one prediction.

### Off the data again: interventional and conditional values


There is a second choice hidden in the interventional definition. Filling in the missing features by drawing them from the background *independently* of the features in the coalition builds rows that combine this tumour's worst radius with another tumour's worst concave points. In this data those two features are correlated at 0.79, so many of the rows built are tumours that do not exist. It is the same problem that Sections 14.2 and 14.3 met in permutation importance and partial dependence: the model is asked about combinations it never saw.

The alternative, *conditional* Shapley values, defines a coalition's worth by drawing the missing features from their distribution *given* the coalition's values, which keeps the rows realistic. It changes the answers again, and it has a cost beyond computation. Under the conditional definition a feature the model never uses can receive credit, because knowing its value changes the expected values of the features the model does use. Janzing and colleagues argue that the interventional version is the right one for asking what the *model* does; Sundararajan and Najmi catalogue how the variants disagree. The choice between them is a second "compared with what?" that the uniqueness theorem leaves open.

What the theorem does guarantee is useful: given a model, a value function and a background, the split is unique and adds up. The table below shows how far apart the backgrounds put the starting point. The skill lies in stating the question, and an explanation is only as meaningful as its stated reference.

![The base value is the explanation's "compared with". A background of benign tumours puts it at +8.4, so every explanation becomes an account of why a tumour is less benign than those. The ranking by mean size is the same in every row.](ml118-f2-table.png){alt="A four-row table of base values and mean absolute attributions: base values range from -8.5 to +8.4."}

### Choosing the background deliberately


If the background is a choice, it should be made like one. Three questions decide it.

**Who is asking, and compared with whom?** A patient asking why their tumour was flagged is comparing it with tumours that were not; a regulator asking why the model behaves as it does across a population is comparing with the population. The first calls for a background of unflagged cases, the second for the whole training set. Here the benign background and the all-tumours background disagreed on the leading feature for 58% of tumours.

**Is the background made of real rows?** A single row of feature means is cheap and is not a tumour anyone has; it flipped 19% of signs. A sample of real rows, even a few hundred, costs more and answers a question about real cases.

**Is the background stated?** An explanation without its reference is like an effect size without its baseline. A sentence of the form "this feature added so much to the log-odds, relative to the average benign tumour" can be checked and argued with; "this feature was the most important" cannot.

A useful habit is to show two backgrounds side by side whenever an explanation matters. Where they agree, the explanation is robust to the choice. Where they disagree, as for more than half the tumours here, the disagreement is itself the honest answer. All of this holds one fitted model fixed; Section 14.5 asks whether a model's accuracy alone can tell us that what it relies on is the task at all.

## A Planted Shortcut Wins the Test Set and Loses Everywhere Else

<!-- source: ml-19-shortcut; hero: ml119-hero.png -->


Sections 14.1 to 14.4 were about reading what a model has learned, and each found that the reading depends on a question the method does not state. This section asks whether reading is necessary at all when the model is simply accurate. The working assumption of most model selection is a single sentence: *the model with the better held-out score has learned the task better.* Practitioners rely on it every time they choose between two models by a test score or a cross-validated score. A held-out set can check that sentence only if it differs from the training set in the ways the world will. If it does not, a model can earn its better score by exploiting something about how the data were collected, and the score will reward it for exactly the behaviour that fails in use.

This section plants such a feature in the handwritten digits, where its effect can be measured exactly. It defines a shortcut and describes the planted one. It compares a model trained with the shortcut and a model trained without it on several test sets, and shows how the comparison depends on how reliable the shortcut is. It then shows how the shortcut could be caught, and explains why no amount of held-out data drawn like the training data can, by its score alone, separate the two models.

### Shortcuts, and why planting one makes them measurable


A *shortcut* is a feature that predicts the label in the data for a reason unrelated to the task. Published examples include hospital-specific markers on chest X-rays that predicted pneumonia because one hospital saw sicker patients, watermarks on photographs of horses, and the time of day a scan was taken. In each case the feature is genuinely predictive in the data the model was trained and tested on, because the same collection process produced both. Real shortcuts are hard to measure because nobody knows they are there, so there is no clean version of the data to compare with. Planting one makes the comparison possible.

The data are the UCI handwritten digits as bundled with scikit-learn: 1,797 images of 8 × 8 pixels, each pixel an intensity from 0 to 16. A few pixels at the edges are blank, or hold at most a trace of ink (an intensity of at most 1 of 16), in every image. The experiment assigns one such pixel to each of four classes, 3, 5, 8 and 9, and sets it to full intensity on a chosen share of that class's images, in training and test data alike. That is the kind of mark a scanner artefact or a label printer might leave. The share, called the *rate* below, runs from 0% to 100%.

A random forest of 300 trees is trained on the marked training images, and each result is the mean over three stratified half splits, each with about 900 test images. The forest is scored on three test sets:

- **same-shortcut test**: the test images marked at the same rate as the training images, which is what a standard random split would provide;
- **clean test**: the same test images with no markers;
- **wrong markers**: the test images with each class's marker moved to a different class, the 3s' marker onto the 5s and so on.

```python
from standarderror.ml import reading as rd

# marker pixel on `rate` of the 3s, 5s, 8s and 9s, train and test
for r in rd.shortcut_study(rates=(0.0, 0.5, 0.9, 1.0)):
    print(f"rate {r['rate']:4.0%}  same-shortcut test {r['same']:.3f}"
          f"  clean test {r['clean']:.3f}  wrong markers {r['wrong']:.3f}")
```

```text

rate  90%  same-shortcut test 0.986  clean test 0.947  wrong markers 0.663
rate 100%  same-shortcut test 0.991  clean test 0.884  wrong markers 0.598
```

The first row is the control. With no marker in training, the first two test sets contain the same images, and the clean forest scores exactly the same, 0.971, on the third set too: lighting pixels it never learned to use changes none of its answers. At a rate of 90%, the shortcut model scores 0.986 on a test set drawn like its training set, better than the clean model's 0.971. Any model-selection procedure that compared the two on that test set, cross-validation included, would pick the shortcut model. The figure below plots the scores against the rate.

### What the better score bought


The other columns show what the shortcut model learned. On clean images it falls to 0.947, below the clean model. On the four marked classes alone, it gets 0.895 of clean images right, against 0.954 for the clean model. It has learned that a 3 is, in large part, an image with a pixel lit in the top-left corner, and it is less sure what a 3 looks like without one. Move the markers to the wrong classes and it scores 0.663.

The trend is monotone in the shortcut's reliability, in every column of the table later in this section. At a rate of 50%, the marker's gain on its own test set, 0.002, is within noise, while the clean score has already fallen by 0.007. At 100% the same-shortcut score is 0.991, the best of any model here, and the clean score is 0.884, the worst. The more perfectly the shortcut predicts the label in the data, the more the model leans on it, and the less of the real task it learns.

A plausible mechanism, though the trees were not inspected here, is ordinary greed. A tree chooses each split to separate the classes as well as possible, and a lit pixel that occurs almost only in 3s separates them in a single split, more cleanly than any combination of strokes. Once the marker has routed most 3s away, fewer splits on stroke shape are needed, and the fewer exceptions the marker has, the fewer such splits the trees learn.

None of this is a malfunction. The forest was asked to predict the label from 64 pixels as accurately as possible, on data in which one pixel predicts four classes almost perfectly. It did. The test set agreed, because it was built the same way. A test score measures how well the model fits the *data-generating process* of the test set, the whole procedure by which rows and labels came to be, and that process included the shortcut. Three checks generalise beyond planted pixels.

1. **Look at what the model relies on and ask whether it should matter.** An importance ranking is most useful as a list of things to be surprised by.
2. **Score the model on a slice where the suspected shortcut is absent or broken.** Here that is clean images of the marked classes, where accuracy fell from 0.937 at a rate of 50% to 0.895 at 90%.
3. **Evaluate on data from a different source**: another hospital, another scanner, another year. This *external validation* is the most expensive check and the most informative. A shortcut tied to how one dataset was collected rarely survives a change of collection.

### Why held-out data cannot see it


It is worth being precise about what failed. It was not the size of the held-out set, and it was not its independence from training: the test images were never seen by the model. What failed is the assumption that the test set represents the conditions under which the model will be used. Every test image was produced by the same process as the training images, marker included, so a model that exploits the process is rewarded twice, once in training and once in testing.

Cross-validation inherits the same blind spot, because its folds are cut from the same data. So does any metric computed on a random split, however many times the split is repeated, and so do the error bars of Section 1.1: they quantify sampling noise around the score on data produced by this process, which is the wrong target if the process will change. A bigger test set would only make the shortcut model's advantage, 0.015 here, more significant.

The only evidence that can separate the two models comes from a different process: images without the marker, images in which the marker means something else, images from another source. In this experiment those cost nothing to make. In practice they cost a second site, a second device or a second year of data, and that cost is one reason so many published models are evaluated only on a random split of one dataset. Section 1.2 met a subtler limit of the test score, that models which tie on it can still give different answers to the same rows; this section has met a blunter one, that a score earned on data from one process says little about another. Chapter 15 turns to the rows themselves: how they come to be missing, selected or shifted.

## In practice

### Reading an importance ranking

- **Do not read the default importance chart as a ranking of what matters.** `feature_importances_` in scikit-learn's forests is MDI, computed on the training rows. Treat it as a description of where the trees split, not of what the model needs.
- **Add noise columns as a baseline.** Add one standard-normal column and one fair-coin column before fitting. Any real feature that ranks below the continuous noise column has an impurity importance you cannot distinguish from nothing.
- **Be most suspicious where features differ in cardinality.** When binary flags sit beside continuous measurements, identifiers, timestamps or high-cardinality codes, expect MDI to favour the latter. Check whether identifier-like columns should be in the model at all.
- **Constrain the trees if you must use MDI.** A minimum leaf size reduces the bias, but it did not remove it in Section 14.1; do not treat it as a correction.
- **Use permutation importance on held-out rows, and say which question it answers.** Compute it on data the model was not trained on, and report its uncertainty across repeats or resamples. It measures the reliance of this fitted model on the column, not importance to the outcome.
- **Compute drop-column importance for the top features.** For the handful of features that matter to a decision, refit without each and compare with its permutation importance. Where the two disagree by more than a factor of two, look for other columns that carry the same information.
- **Look for near-copies before ranking.** Compute the correlation matrix of the inputs, group features above a threshold, and report importance per group, by joint permutation or by refitting without the group.
- **Check how many shuffled rows are realistic.** For the strongest correlated pairs, plot the pair before and after shuffling and count the shuffled rows outside the real cloud. If the share is large, consider conditional permutation or grouping.
- **Do not prune on a low or negative permutation importance alone.** A correlated partner may be covering for the feature; removing both may cost as much as the feature was ever worth.

### Reading an effect plot

- **Check correlations before reading a partial dependence plot.** For the feature plotted, find the feature it is most correlated with. If the correlation is high, treat the PDP as a description of the model off the data, not of the data.
- **Draw the support check.** Scatter the pair and overlay the rows the PDP evaluates at its lowest and highest grid values. Report the share that falls inside the real cloud alongside the plot.
- **Use ALE when features are correlated.** Twenty quantile bins are a reasonable start. Overlay ALE and the PDP; where they disagree, the PDP is reporting the model off the data.
- **Do not take ICE curves as a fix.** They show heterogeneity across rows but evaluate the same off-data rows.
- **Treat any plot of one feature as incomplete when effects interact.** If the effect of one feature depends on another, a single curve averages over that dependence; look at two-feature plots instead.

### Explaining a single prediction

- **Name the background in every explanation.** Write "compared with the average benign tumour, this one's concavity added …", not "concavity was the most important feature".
- **Choose the background from the question.** Use the cases the person asking regards as normal: unflagged cases for an individual who was flagged, the whole population for a question about the model's behaviour overall.
- **Prefer a sample of real rows to a single row of means.** The means shortcut has a base value close to the default and can still flip many signs.
- **Show two backgrounds when an explanation matters.** Report agreement in the top features as evidence of robustness, and disagreement as part of the answer.
- **State the scale and the definition.** Say whether attributions are in log-odds or probability, and whether they are interventional or conditional.
- **Do not infer individual explanations from global bar charts.** A stable ranking of mean absolute values says nothing about any one prediction.

### Checking what an accurate model relies on

- **List the features that describe how a row was collected.** Source system, site, device, batch, timestamp, file format, or an ID that encodes any of these. Find where each falls in the importance ranking.
- **Treat a surprising top feature as a finding.** If a feature that should not matter to the task ranks near the top, investigate before shipping.
- **Score on slices where the suspected shortcut is broken.** Split the test set by collection variables and score each part separately; if one part is much worse, find out what the model is using on the other.
- **Keep an external test set.** Data from another site, device or period is the only evidence that can separate a model that learned the task from one that learned the collection process.
- **Do not let a larger or repeated random split stand in for a different source.** It narrows the error bar around the same target.

## Limits of the evidence

### Impurity importance (Section 14.1)

- **Permutation importance needs held-out rows.** Computed on the training data, permutation importance should inherit much of the same bias, since the forest has memorised the noise feature's values there and shuffling them hurts. That version was not run; the fresh rows are what make the numbers in Section 14.1 honest.
- **Categorical coding matters.** There the categories are coded as integers, which is what scikit-learn's forests see. *One-hot coding*, which gives each level its own binary column, would change which columns MDI favours; whether it removes the preference for many split points was not tested.
- **Corrected MDI exists.** Out-of-bag versions of impurity importance, which score each tree's splits on the rows left out of its bootstrap resample (the *out-of-bag* rows, the subject of Section 7.2), and the debiased MDI of Li et al. (2019) score splits on rows the tree did not train on, which is designed to remove most of this bias. They are not what the default `feature_importances_` attribute reports.
- **Twenty datasets per setting.** The counts quoted are per dataset, and they are not all unanimous. With no signal, MDI rose with the number of distinct values in all 20 datasets. With signal, it ranked the binary feature last in 19 of 20 and first in none; permutation importance ranked it first in 95%. With leaves of 20 the picture is mixed: MDI ranked the binary feature first in 25% of datasets and last in 5%. The mean shares carry standard errors of at most 0.004 with fully grown trees and up to 0.022 with leaves of 20.

### Permutation importance (Section 14.2)

- **Refitting answers its own question, with its own distortion.** Drop-column importance measures what the *data* lose without a feature, given the model class. It is expensive, needing one refit per feature, and it assigns zero to every member of a group of near-copies, which is equally misleading in the other direction. The honest unit is often the group.
- **$R^2$ on 133 test patients is noisy.** The numbers are averages of three splits, and single splits differ a lot: test $R^2$ ranged from 0.26 to 0.42, and the loss from refitting without bmi from -0.07 to +0.13. The direction held in every split, since permuting bmi always cost more than refitting without it, but the size of the drop-column numbers, in the text and in the table, is uncertain to about a tenth of $R^2$.
- **Other models distribute reliance differently.** A linear model with an exact copy has no unique coefficients at all, and neither does a lasso: any division of the coefficient between the two columns with the same sign has the same penalty, so the answer depends on the solver. With near-copies, Section 6.3 found the lasso's choice between the two varying from fit to fit. Permutation importance inherits whatever the fitting procedure did.
- **A copy is the extreme case.** At correlation 0.8 the forest still preferred the original and the copy's permutation importance was near zero; at 0.95 the copy started to take a share, and the original still dominated. Most real pairs sit somewhere in between, and so does the distortion.

### Partial dependence (Section 14.3)

- **Individual conditional expectation curves inherit the problem.** ICE plots show each row's curve $v \mapsto \hat f(v, x_{i,C})$ instead of their average. That reveals heterogeneity between rows, but it evaluates the same off-band rows.
- **Two features is the easy case.** In ten dimensions, "off the data" is the normal state of a modified row, and checking a two-dimensional scatter will not reveal it. ALE's local moves are the safer default whenever features are correlated at all.
- **The truth in the simulation is additive.** With an interaction between $x_1$ and $x_2$, the effect of $x_1$ depends on $x_2$ and no single curve captures it. ALE's second-order plots and the functional-ANOVA decomposition, which splits a function into main effects and interaction terms, address that; one-dimensional plots do not.
- **Three datasets per setting.** Single datasets move the slopes by up to about a tenth; the forest's ALE slope at the highest correlation ranged from 0.83 to 1.03. In every dataset, though, the PDP's slope fell as the correlation rose and stayed far below the ALE's.

### Shapley values (Section 14.4)

- **Five features is a toy for enumeration.** Exact computation costs $2^p$ model evaluations per background row. Practical explainers sample coalitions or exploit the structure of trees; their answers approximate the same quantities and inherit the same dependence on the background.
- **Log-odds, not probabilities.** Attributions computed on predicted probabilities are different numbers from those computed on log-odds, and libraries differ in which they report. Everything in Section 14.4 is in log-odds. The dependence on the background is part of the definition on either scale, but its size was measured on this one only.
- **One model, one split.** A different model fitted to the same data could rank the features differently for the same tumour even with the background fixed. That was not measured; Section 1.2 shows that models of near-equal accuracy can disagree on the predictions themselves, which is a reason to expect it. Section 22.2's rerun on other splits narrowed the benign background's effect on the top feature to between 33% and 53% of tumours.
- **Global summaries average the problem away.** Mean absolute Shapley values, the usual "SHAP importance" bar chart, rank the five features in the same order under all four backgrounds, while their sizes move by up to 49% and the leading feature of individual explanations changes for up to 58% of tumours. That stability of the ranking is real and says nothing about any one prediction.

### Shortcuts (Section 14.5)

- **A planted shortcut is obvious once named.** One lit pixel is easy to find. Real shortcuts are spread over many features, such as texture, background or image statistics, and importance methods find them only partly, which is why external validation matters more than any explanation.
- **A forest, not a network.** Deep networks are often argued to be, if anything, more prone to shortcuts, because they tend to pick up the simplest predictive features first; Geirhos and colleagues review the evidence. No network was trained here. The direction of the result should not depend on the model; its size will.
- **The shortcut is perfectly stable here.** In practice a shortcut's reliability drifts, as when a hospital changes scanners, and a model that leaned on it fails gradually, which is harder to notice than a collapse.
- **Three splits.** The scores are means over three half splits of about 900 test images each, so differences of a few thousandths are within noise. That includes the 50% marker's gain on its own test set; the other gaps quoted are several times larger.

## Key points

1. Impurity importance (MDI) is computed on the training data and credits every split, so features with more distinct values get more chances to split and more credit. With no signal anywhere, it gave a continuous feature 42% of the importance and a binary one 5%, in order of distinct values in all 20 datasets.
2. With a real effect on the binary feature alone, MDI never ranked that feature first and ranked it last in 19 of 20 datasets; permutation importance on fresh data ranked it first in 95%. Larger leaves reduced the bias without removing it, and on data with strong signals it barely shows. It matters most where importance charts are most tempting: weak effects, mixed feature types, deep trees.
3. Permutation importance measures how much one fitted model leans on a column, not how much the outcome depends on it or how much the data would lose without it. On the diabetes data, shuffling bmi cost 0.168 of test $R^2$; refitting the forest without it cost 0.043.
4. Near-copies hide each other: with an exact copy, the two columns' permutation importances summed to 0.038, a quarter of bmi's alone. Group correlated features and report what is lost when the group is removed.
5. Shuffling a correlated feature invents rows: 29% of shuffled (s1, s2) pairs lay outside the region holding 99% of real ones. Setting a feature to a grid value in every row, as a partial dependence plot does, invents rows in the same way.
6. With $x_1$ and $x_2$ correlated at 0.985, a forest's PDP showed a slope of 0.30 for an effect of slope 1, and ALE showed 0.92; with independent inputs both were within a few hundredths of the truth. Check a feature's correlation with the others before reading its PDP, and use ALE if it is high.
7. Shapley values are the unique fair split of the difference between a prediction and a reference, and the reference is a choice the theorem does not make. Switching the background from all tumours to benign ones changed the top feature for 58% of tumours on one split (33% to 53% on five others); the feature-means shortcut kept the base value almost unchanged and still flipped 19% of attribution signs.
8. Interventional and conditional Shapley values answer different questions. State the background, the scale and the definition with every explanation you show.
9. A held-out set drawn like the training set rewards any feature that predicts the label in both, shortcuts included. With a marker pixel on 90% of four classes, the shortcut model beat a clean model on the test set (0.986 to 0.971) and lost on clean images (0.947), on the marked classes (0.895 to 0.954) and badly when the markers moved (0.663); the more reliable the shortcut, the higher the test score and the lower the clean score.
10. Permutation importance ranked the marker pixel first of 64. A feature that should not matter at the top of an importance chart is a finding; evaluate on data collected differently before believing that a better score is a better model.

## Exercises

1. Add two columns to your training data: one of standard-normal noise and one of fair coin flips. Refit your forest and look at where they land in its `feature_importances_`; every real feature ranked below the noise column is one whose impurity importance you cannot distinguish from nothing. Then compute permutation importance on a held-out set and compare the two rankings. Where they disagree, find out how many distinct values each disputed feature takes.
2. Explain why a binary feature can contribute to MDI at most once on any path from the root, while a continuous feature can contribute many times, and why this matters more for fully grown trees than for trees with large leaves.
3. Compute permutation importance for one of your models and, for its top five features, the drop-column importance when each is removed and the model refitted. Where the two disagree by more than a factor of two, list the features most correlated with the one in question.
4. Explain in words why the permutation importances of a feature and its exact copy need not add up to the importance the feature had alone, and why the drop-column importance of the pair removed together does not suffer from the same problem.
5. Pick your most strongly correlated pair of features, shuffle one of them in a copy of your test set, and plot the pair before and after; count the shuffled rows that lie outside the real cloud. Then, for a feature whose partial dependence plot you have shown someone, scatter it against the feature it is most correlated with and draw the vertical lines of rows the PDP evaluates at its lowest and highest grid values. How many of those rows lie inside the cloud? Compute ALE for the same feature, with twenty quantile bins, and overlay the two curves.
6. Explain in words why a forest's partial dependence curve for $x_1$ flattens when $x_2$ closely tracks $x_1$ and carries most of the signal, and why ALE's construction avoids this. Describe a case in which what the model does off the data is the question you need answered, and say which of the two plots you would then use.
7. Take one prediction your model made that someone questioned. Compute its SHAP values against your default background, then against a background of rows from the class or group the person had in mind as "normal", and compare the top three features in each. If they differ, write down, in one sentence, what the reference was for the explanation you would now give.
8. Explain why, for a nonlinear model, a background consisting of a single row of feature means can give a base value close to that of the full training set and still produce different attributions.
9. List the features of your model that describe how a row was *collected* rather than what it *is*, and check where each falls in your permutation-importance ranking. Split your test set by the collection feature most likely to change in deployment and score the model on each part separately. If one part is much worse, find out what the model is using on the other.
10. Explain why a larger test set, or repeated cross-validation, would make the shortcut model of Section 14.5 look more convincingly better, not less.

- Breiman, "Random forests", *Machine Learning* (2001): introduces random forests and the permutation measure of variable importance.
- Li et al., "A debiased MDI feature importance measure for random forests", *NeurIPS* (2019): a corrected impurity importance that scores splits on rows the tree did not train on.
- Efron et al. (2004): the source of the diabetes data used in Section 14.2.
- Strobl et al., "Conditional variable importance for random forests", *BMC Bioinformatics* (2008): shows how correlated predictors distort permutation importance and proposes conditional permutation.
- Hooker, Mentch and Zhou, "Unrestricted permutation forces extrapolation", *Statistics and Computing* (2021): argues that permute-and-predict methods, and methods that edit real rows in general, evaluate models off the data, and reviews alternatives.
- Friedman, "Greedy function approximation", *Annals of Statistics* (2001): introduces gradient boosting and the partial dependence plot.
- Apley and Zhu, "Visualizing the effects of predictor variables in black box supervised learning models", *JRSS B* (2020): defines accumulated local effects and compares them with partial dependence.
- Shapley, "A value for n-person games" (1953): the original definition of the value and the uniqueness theorem.
- Lundberg and Lee, "A unified approach to interpreting model predictions", *NeurIPS* (2017): brings Shapley values to model explanation as SHAP.
- Janzing, Minorics and Bloebaum, "Feature relevance quantification in explainable AI: a causal problem", *AISTATS* (2020): argues for the interventional definition when explaining what a model does.
- Sundararajan and Najmi, "The many Shapley values for model explanation", *ICML* (2020): catalogues the variants of Shapley-based attribution and where they disagree.
- Geirhos et al., "Shortcut learning in deep neural networks", *Nature Machine Intelligence* (2020): defines shortcut learning and reviews the evidence across vision and language models.
- Zech et al., "Variable generalization performance of a deep learning model to detect pneumonia in chest radiographs", *PLOS Medicine* (2018): a pneumonia detector whose performance varied across hospitals, partly because it picked up which hospital an X-ray came from.
- Lapuschkin et al., "Unmasking Clever Hans predictors", *Nature Communications* (2019): explanation methods revealing classifiers that relied on watermarks and other artefacts.
